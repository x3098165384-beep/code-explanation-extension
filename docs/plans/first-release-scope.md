# 首版范围确认

2026-10-21 开始，使用 grill-with-docs，沿用[已有讨论记录](initial-design/discussion-notes.md)。Q1 至 Q8 一次确认一个问题；Q8 后请求者允许一次提出多个问题。暂不实现插件。

## 已确认

### 支持的修改比较

首版同时支持：

- 尚未提交的修改，对照修改前的代码阅读当前改动。
- 两个 Git 提交之间的修改。

请求者在 Q1 选择两种都需要。

### 尚未提交的修改

比较最近一次提交与当前文件，包含已暂存和未暂存的全部改动。首版不单独提供暂存区比较。

请求者在 Q2 选择一起查看全部尚未提交的修改。

### 代码引用和变化检查

首版不额外保存源码，讲解引用项目文件或 Git 版本，并检查讲解是否仍然对应代码。

请求者在 Q8 明确确认此方案，替代 Q3 和 Q5 中保留当时代码的决定。普通脚本讲解和两类 diff 的首版支持范围保持不变。

未提交的代码后来被修改时，旧讲解不能保证还原当时的完整代码。引用及检查信息的具体格式尚未确定；代码变化后的处理遵循后文 Q11、Q12 的决定。

已核对 [CodeTour 的代码读取实现](https://github.com/microsoft/codetour/blob/main/src/utils.ts)：普通步骤可以按路径读取当前工作区文件，也存在读取 Git 版本或附带代码内容的分支。[官方说明](https://github.com/microsoft/codetour#exporting-tours)将附带文件内容用于导出分享，不要求每份普通讲解都复制源码。引用当前文件并不保证代码变化后旧讲解仍然正确，额外保留旧代码应作为单独需求确认。

### 讲解的准备方式

首版插件只读取和展示讲解，负责打开讲解文件、显示行内讲解和顺序跳转，不提供手动编写界面或内置模型调用。

请求者在 Q4 倾向选择 A，并提出实际使用方式：向外部 agent 请求讲解某个脚本，由 agent 通过外部 harness 生成讲解文件。插件应有明确的文件格式，让外部工具能够准备讲解内容及其代码引用。文件类型已在 Q7 确认为 Markdown，定位和引用的具体约定尚未确定。

### 普通脚本讲解

首版包含没有代码修改时的普通脚本讲解，与 diff 讲解并列支持。源码引用及变化检查按 Q8 的决定处理。

请求者在 Q5 明确确认这一范围。两个名称的含义记录在根目录 `GLOSSARY.md`。

### 不兼容 CodeTour 文件

请求者在 Q6 确认首版和后续版本都不兼容 CodeTour 的 `.tour` 文件，并提出直接使用 Markdown 或 HTML，以便外部工具生成和通用阅读。

### Markdown 讲解文件

请求者在 Q7 确认使用 `.md` 文件，正文使用 Markdown，另行约定定位和代码引用信息。首版不读取独立 HTML 文件。

Markdown 的选择不代表行内显示效果已经得到验证。VS Code 的 [MarkdownString 文档](https://code.visualstudio.com/api/references/vscode-api#MarkdownString)说明其 HTML 支持限于部分标签和属性；[Webview 文档](https://code.visualstudio.com/api/extension-guides/webview)说明可自定义网页界面的承载位置包括独立编辑页、侧栏和面板。不能据此承诺任意网页排版都能放在原生代码行内。

### 跨文件阅读

请求者在 Q9 选择 A：一份讲解可以跨多个文件，按 agent 安排的步骤顺序阅读，可以先解释调用处，再跳到另一个脚本的具体实现。

### 一步 diff 讲解对应的代码

请求者在 Q10 选择 A：一步 diff 讲解可以只指向一侧，也可以同时指出改前、改后两侧的相关代码。两侧代码如何显示和突出，尚需实际验证。

### 某一步无法对应代码时

请求者在 Q11 选择 A：检查发现某一步对应的代码已变化或找不到时，说明原因，正文仍可阅读，但不把讲解显示在可能错误的代码旁。其他有效步骤可以继续。

### 代码位置变化

请求者在 Q12 选择 A：代码内容未变、位置变化时尝试重新定位。能唯一确认对应代码时继续；找不到或存在多个可能位置时，按 Q11 提示，不自行选择一个可能错误的位置。

### 显示和导航

请求者在 Q13 接受推荐：每次只显示当前一步的行内讲解，提供上一步、下一步、可直接跳转的步骤列表，以及当前步骤编号和总数。切换步骤后移除上一步的行内讲解。

### 打开讲解

请求者在 Q14 选择 A：通过“打开讲解”手动选择一个 `.md` 文件开始阅读。首版不自动扫描约定目录来生成讲解列表。

### 讲解文件更新

请求者在 Q15 选择 B：agent 更新正在阅读的 `.md` 文件并保存后，自动加载新内容，更新正文和步骤。

请求者在 Q18 选择 A：自动更新后保留当前步骤；正文或顺序变化后仍阅读同一步；如果该步骤被删除，则回到第一步。

请求者在 Q19 选择 A：更新后的讲解文件无效或暂时无法读取时，保留上一次成功加载的讲解，明确提示新内容尚未加载；文件修好后自动更新。原讲解仍需通过代码对应检查。

### 阅读进度

请求者在 Q16 选择 B：记住上次读到的步骤，下次主动打开同一份讲解时恢复；如果该步骤已被删除，则从第一步开始。启动 VS Code 时不自动打开讲解。

### 混合阅读

请求者在 Q17 选择 A：同一份讲解可以混合普通脚本步骤和 diff 步骤，按步骤打开对应的普通文件或 diff。例如先解释某个方法的修改，再解释没有修改的调用方。

### 停止和读完讲解

请求者在 Q20 接受推荐：提供“停止讲解”操作；停止后清除行内讲解和代码突出显示，保留已打开的代码页及阅读进度。读到最后一步时保留该步内容，由请求者决定何时停止。

### 未保存的源码修改

请求者在 Q21 选择 A：检查编辑器当前内容，包括未保存的修改。仍能对应就显示，否则按 Q11 提示。插件不自动保存源码。

### 同一个 Markdown 文件保存全部讲解信息

请求者在 Q22 选择 A：正文、定位和代码引用等信息全部放在同一个 `.md` 文件中。正文使用 Markdown，其余信息用约定的备注记录；不要求额外的配套信息文件，也不额外保存源码。

### 无法定位时阅读正文

请求者在 Q23 选择 A：打开原 `.md` 中该步骤的正文，同时说明无法定位的原因。其他有效步骤仍可继续行内阅读，不为无效步骤另做独立阅读面板。

## 后续规格与实际验证

Q1 至 Q23 的首版使用范围已经逐项确认。范围确认阶段列出了以下格式设计和技术验证工作，后续进展见本节末尾；这些要求本身不能证明插件已经可用：

- 定义 Markdown 中定位、代码引用及对应关系检查信息的具体字段和格式，提供外部 agent 可照着生成的完整示例。
- 定义如何识别同一份讲解和同一步骤，以支持自动更新后保留步骤，以及重新打开时恢复进度。
- 明确读取不到文件或 Git 版本时的错误说明。相关步骤按 Q11、Q23 处理，不自行替换成其他文件或版本。
- 代码内容相同但位置变化时，验证唯一匹配的重新定位，以及无匹配、多个匹配时的提示。
- 在 VS Code 中实际验证普通文件、删除行、新增行、同一步关联 diff 两侧，以及跨文件混合步骤的显示和跳转。
- 用真实的逐句讲解检查 Markdown 阅读效果，保留不改源码、行内显示和顺序阅读的要求。
- 验证讲解文件自动更新、无效更新后的继续阅读、停止后的清理，以及进度恢复。

范围确认阶段仅记录决定，没有创建插件代码或实施上述验证。后续已按请求使用 to-spec 整理[首版规格](../../.scratch/first-release/spec.md)、[Markdown 文件约定](../../.scratch/first-release/explanation-format.md)及[完整讲解示例](../../.scratch/first-release/explanation.example.md)，并将尚未完成的验证列为后续要求。示例数据的一致性检查不等于 VS Code 运行验收。

2026-10-21，任务 01 已在真实 VS Code 1.142.0 中完成固定案例的行内 Markdown、diff 两侧定位、跨文件步骤切换、当前未保存内容、新增及删除文件、无效版本处理和停止清理检查；请求者手动提供截图，代理核对运行记录。结果及限制见[任务 01 运行记录](../../.scratch/first-release/verification/results.md)。正式插件、代码对应检查、自动更新及进度恢复仍未实现，任务 02 至 08 按请求暂不启动。

随后请求者授权多个子代理继续完成任务 02 至 08。正式读取、对应检查、Git 比较、导航、自动更新和进度功能现已接通，类型检查、构建、12 条异步顺序检查及 VSIX 打包通过。新的完整讲解已按实际演示工程生成；正式界面验收由请求者继续手动操作，当前结果见[首版实现记录](../../.scratch/first-release/implementation-results.md)和[26 项验收记录](../first-release-acceptance.md)。

2026-10-21 正式验收中，分号前多一个空格使整步失效。请求者随后明确将能确认不影响含义的格式变化纳入首版：当前 JavaScript 可增加整文件和目标的格式摘要，只容许代码符号之间的空格、Tab 与缩进变化；代码符号、字面值、注释和换行须全部对应。原文与格式候选统一检查唯一性。固定 Git、其他语言及缺少摘要时保持严格，不做语义猜测。此决定取代此前对所有缩进变化一概失效的预期，实际格式与边界见更新后的规格和文件约定。
