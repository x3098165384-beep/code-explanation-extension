# 使用行内代码讲解

本文对应 0.2.0。讲解使用版本 2 JSON；旧 Markdown 需要由外部 agent 一次性转换。文件约定见 [JSON 格式](../.scratch/reading-experience/explanation-format.md)，实际通过范围见[后台验收记录](background-verification.md)。

## 安装和打开

手动在 VS Code 中执行“Extensions: Install from VSIX…”，选择项目中生成的 `code-explanation-extension-0.2.0.vsix`，按提示重新加载。后台验证使用独立配置，不会更新你正在使用的 VS Code 窗口。

打开代码所属项目，点击左侧“行内代码讲解”图标。默认把讲解放在项目根目录的 `.code-explanations/`；侧栏读取该目录和子目录中的 JSON。可在项目设置中更改 `codeExplanation.directory`，填写项目内的相对目录。打开侧栏不会创建目录或开始阅读。

展开讲解查看步骤列表；点击讲解标题从已记录步骤继续，点击步骤直接阅读该步。侧栏显示当前步骤，和状态栏的“上一步”“下一步”“选择步骤”共用同一阅读位置。

也可执行“行内代码讲解：打开讲解”选择目录以外的 JSON。多个项目同时打开时，明确选择代码所属项目；代码路径相对该项目解析，不根据讲解的位置猜测。

“继续上次讲解”和最近打开列表按项目保存。重启不自动打开代码或开始阅读，主动选择后才恢复位置并重新检查代码。文件缺失或格式错误时，提示具体文件和原因；失败的打开不替换原有有效阅读。

## 行内阅读和复制

普通步骤显示在对应源码旁；diff 步骤打开真实比较，有改后目标时正文显示在改后侧，否则显示在改前侧。双侧目标都必须检查通过，正文只显示一份。

代码框使用真实文字。直接拖选几个字符或几行，再按普通复制快捷键；点击“复制这段代码”复制整个代码块。复制保留代码的缩进、Tab、换行和特殊字符，不包含按钮或说明文字。代码框下面是按执行顺序写的简短中文翻译。长行可以横向滚动，外观随深浅主题显示。

“查看正文”打开排版后的完整讲解并定位当前步骤。该页显示标题、简介和全部步骤，支持选择及整块复制，不要求进入原始 JSON。停止讲解会关闭当前正文页、清除行内讲解及突出显示，保留代码页、列表和已保存进度。

## 代码变化和讲解更新

插件使用编辑器当前源码，包括未保存修改，不会替你保存源码。固定 Git 版本来自讲解记录的完整提交，不切换分支或暂存区。新建未保存源码必须已关联项目内的具体路径，不能靠 `Untitled-1` 猜测文件。

目标内容移动但仍能唯一对应时，重新定位并提示。内容已变、出现多个相同目标、文件或提交不可读时，清除该步的行内讲解及突出显示，说明原因，仍可在正文页阅读。其他有效步骤可以继续。

带 `formattingSha256` 的 JavaScript 当前文件允许可以确认的符号间空格、Tab、缩进变化；整份代码的符号、字面值、注释和换行仍须对应。字符串、模板、正则、注释内部空白及增删换行、分号不放宽。其他语言、固定 Git 和缺少格式摘要的讲解继续严格检查原文。

讲解按已保存 JSON 更新，未保存编辑不替换正文。更新时保留讲解和步骤 `id`：重排保持当前步骤，删除当前步骤回第一步，讲解标识变化视为另一份讲解。其他讲解保存只更新列表，不抢走当前阅读。

无效保存或暂时无法读取时，继续使用上一次成功加载的讲解，并明确标注，源码仍重新检查。修好并保存后自动更新。更换文件或把旧 Markdown 转到另一位置，不保证迁移旧进度。

## 让外部 agent 生成讲解

使用 **Teach with Code Explanation** skill，明确代码项目、需要讲解的脚本或修改。输出版本 2 JSON，默认位于 `.code-explanations/`；结构与检查要求见 [JSON 格式](../.scratch/reading-experience/explanation-format.md)和[完整示例](../.scratch/reading-experience/explanation.example.json)。

正文按实际执行顺序分成短代码块和下面的简短翻译，说明对象、条件、动作和结果，不逐个讲解语法，也不把场景例子放在代码解释之前。读取实际代码、使用完整提交并计算摘要，不照抄示例引用。已有讲解更新保留标识。

构建插件后，从代码项目执行 `node <插件项目路径>/tools/code-reference.cjs src/example.js 4 5`，可生成当前文件引用和目标。`--stdin` 可接收外部工具实际取得的编辑器文本；默认只读磁盘，不能声称包含未保存修改。旧讲解转换保留原文件、正文和所有引用，不重新计算摘要掩盖代码已失效。

插件不调用模型，不提供生成、录制、编辑、插入或执行代码的功能，不支持 `.tour` 或独立 HTML。作者 HTML 按文字显示，正文不获准执行任意 VS Code 命令。讲解不额外保存完整源码，不能恢复丢失的未提交代码；文本对应也不代表业务说明已重新核对。

## 构建和独立验证

在插件项目目录中执行：

```powershell
npm.cmd install
npm.cmd test
npm.cmd run check
npm.cmd run package
```

需要手动调试时，在 VS Code 中打开插件项目，按 F5，选择“运行行内代码讲解”。这会打开验证窗口，应由你操作。代理只运行已授权的独立后台实例。

`node tools/prepare-acceptance.cjs --directory=<新的完整路径>` 生成独立 Git 工程、`lecture-disk.json`、`lecture-unsaved.json` 和 `manifest.json`。已有目录默认拒绝覆盖，旧手测目录不自动改写。两份讲解分别对应磁盘内容及指定的未保存编辑，真实路径和提交见 manifest；插件读取 JSON 不依赖 manifest。

演示第六步的未保存版本要求在演示编辑器中把 `return subtotal;` 改成 `return subtotal + 2;` 并保持未保存；没有这项编辑时不对应是预期结果。其余步骤涵盖普通文件、历史文件、diff 删除行、新增行、双侧目标、整文件新增和删除。

`npm.cmd run test:background` 打包后使用独立 Windows 窗口环境、配置及案例工程验证并截图。它不切换或操作当前窗口，复制检查使用和用户桌面分离的剪贴板。运行方法、结果和限制见[后台验收说明](background-verification.md)。
