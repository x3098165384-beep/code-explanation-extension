# 首版使用与手动检查

本说明用于启动当前扩展、生成真实讲解并执行验收。任务 01 已有最小验证扩展的截图；正式插件的新读取、对应检查、自动更新和进度流程仍须在真实 VS Code 中逐项观察。本文件中的操作和预期结果不等于已经通过。

## 构建和启动

在插件项目目录 `F:\Sync\MyProjects\code-explanation-extension` 中执行：

```powershell
npm.cmd install
npm.cmd run check
npm.cmd run build
```

用 VS Code 打开这个插件项目，按 F5，选择“运行行内代码讲解”。此操作会打开 Extension Development Host，也就是加载本地扩展的验证窗口。应在你方便操作窗口时手动执行；代理需要启动、聚焦、重载或操作窗口时，先向你申请。

在新的验证窗口中打开要阅读的项目文件夹。讲解引用的路径相对所选项目根目录：只有一个项目时直接使用，打开多个项目时明确选择；没有打开项目时先打开项目文件夹。不要把讲解文件所在目录误当成代码项目。

按 `Ctrl+Shift+P`，执行“行内代码讲解：打开讲解”，手动选择一份有效 `.md` 文件。扩展不会扫描目录，也不会在启动时自动开始上一次讲解。

## 准备独立演示工程

在插件项目中执行：

```powershell
npm.cmd run build
node tools/prepare-acceptance.cjs
```

工具只生成本地文件与独立 Git 演示仓库，不会打开任何窗口。目录为 `.scratch/first-release/runtime/acceptance/`：

| 文件或目录 | 用途 |
| --- | --- |
| `project/` | 新的席位账单示例，包含自己的 `.git`；在验证窗口中打开这个文件夹 |
| `lecture-disk.md` | 按工具实际读取的磁盘源码生成，可先直接打开 |
| `lecture-unsaved.md` | 包含同样的完整阅读流程，当前内容比较对应下方手动未保存修改 |
| `manifest.json` | 本次实际提交、讲解标识、步骤标识、摘要和准备后的 Git 状态；不是扩展读取所需的配套文件 |

已有验收目录时，工具默认停止，不覆盖或清空。确认要保留现有工程继续使用后，执行 `node tools/prepare-acceptance.cjs --reuse`；它只确认已有工程及提交，并显示现有路径，不恢复验收前的代码，也不清除你的修改。

生成器作为外部 agent 使用的本地工具，读取这套工程的实际文件和实际 Git 提交，生成新的讲解和步骤标识、行号及 SHA-256 文本摘要。讲解不包含完整源码副本；Git 历史保留在演示工程自己的仓库中。工具生成的 Markdown 是独立文件，插件读取它时不依赖 `manifest.json`。

### 先阅读磁盘内容

在 Extension Development Host 中打开 `project/`，再用“行内代码讲解：打开讲解”选择 `lecture-disk.md`。它有九步：

1. 当前 `src/invoice.js` 的调用与返回。
2. 旧提交中的普通 `src/charge.js`。
3. 固定提交 diff 的改前删除行。
4. 同一个 diff 的改后新增行。
5. 同一步指出 diff 两侧。
6. 最近提交与当前金额计算的比较，含已暂存和未暂存修改。
7. 整个新增的 `src/format-amount.js`，改前侧为空。
8. 整个删除的 `src/legacy-charge.js`，改后侧为空。
9. 回到当前格式化函数，检查最后一步继续保留正文。

使用“上一步”“下一步”或“选择步骤”跳转。应始终只有当前一步的正文和额外高亮；同一比较中的步骤保持真实 diff。只有一个目标时也保留完整比较；有改后目标时，正文只放在改后侧。状态栏显示当前步骤和总数。

### 再阅读未保存内容

在演示项目编辑器中打开 `src/charge.js`，只把 `return subtotal;` 改为 `return subtotal + 2;`，**保持未保存**。再主动打开 `lecture-unsaved.md`，到第六步检查右侧：

- `seats <= 0 || unitPrice < 0` 来自已暂存修改。
- `Math.round(unitPrice * seats * 100) / 100` 来自未暂存修改。
- `return subtotal + 2;` 来自当前编辑器的未保存修改，磁盘仍是 `return subtotal;`。

这三项必须同时出现在最近提交至当前内容的比较中。扩展不能替你保存源码、改变暂存区或用磁盘旧内容替代编辑器内容。如果没有先做指定的未保存编辑，第六步目标不对应是预期结果；其他有效步骤仍应可以阅读。

新建但还没有保存到磁盘的源码也可以阅读和比较，前提是编辑器文档已经关联到项目内的具体路径，讲解引用该路径和实际文本。没有具体项目路径的 `Untitled-1` 无法对应讲解里的相对路径，插件不会猜测它属于哪个文件。

## 行内代码框

0.1.3 将 Markdown 代码块显示为带独立底色、细边框和留白的矢量图，支持常见语言高亮，未知语言保留原文字。长行在代码框内折行，深浅主题切换后重新显示。矢量图只存在于当前评论正文中，不写图片文件或修改源码、用户主题及全局设置。

图片中的代码不能像普通文字那样拖选复制。需要复制时，使用状态栏“查看正文”，在原 Markdown 代码块中选择；图片替代文字可能受 VS Code 过滤，原文始终以 Markdown 为准。正文中的 HTML 仍按文字显示，命令链接不获得执行权限。

## 代码变化后的提示

在普通当前文件步骤前插入空行，目标文本仍只有一份时，应移动到新的正确位置，并提示文件已有其他修改。把目标文本本身改动、删除，或在同一文件再放一份完全相同的目标，原行内正文和额外高亮应清除；提示具体文件及失败原因，并打开该步骤的 Markdown 正文。

默认匹配保留缩进、行尾空格和字符；仅统一换行风格，并去掉文档开头的一个 BOM（文本开头的编码标记）。带 `formattingSha256` 的 JavaScript 当前文件可允许符号之间的空格、Tab 和缩进变化，并提示“代码格式已变化”。完整文件的代码符号、字面值、注释和换行必须对应，位置仍须唯一。字符串、模板文本、正则或注释内部空格不放宽；增删换行、其他代码也变化、解析失败、缺少新摘要或其他语言时继续严格检查。固定 Git 内容始终核对原文。某一步不对应只影响该步，其他步骤仍可继续。

已有演示工程可执行 `node tools/prepare-acceptance.cjs --formatting`，另建 `lecture-formatting.md`。它保留原来九步内容，第 6 步仍对应未保存的 `return subtotal + 2;`，并增加格式摘要；代码、原讲解和 Git 均不改写。已有同名文件时拒绝覆盖。安装新版插件后，用新文件测试分号前空格和缩进变化，以及修改运算符后立即清除正文；旧讲解缺少格式摘要时保持严格。

整个文件新增或删除时，空白一侧必须来自已确认的“不存在”。不存在的 Git 提交、读不到的文件和实际存在的空文件是不同情况，不能都显示成读取成功的空白内容。产生新 Git 提交后，旧讲解的未提交比较应要求更新基准；原来的固定提交步骤继续使用已记录的提交。

## 保存讲解、回看正文和恢复进度

讲解按磁盘已保存内容更新；只在编辑器里修改讲解但未保存，不会替换当前讲解。外部 agent 更新时保留同一讲解及已有步骤的 `id`，修改正文、标题或顺序后保存，阅读应继续停在相同的步骤标识。当前步骤被删除则回第一步；讲解 `id` 改变则按另一份讲解从第一步开始。

保存不完整 JSON、重复步骤标识或其他结构错误时，应提示新内容没有加载并保留上一次成功加载的内容。保留的旧讲解仍要对照当前源码检查。文件修好并保存后应自动更新，解除文件错误提示。

无效步骤通常回到原 `.md` 对应标题。如果原文件已经损坏、暂时读不到，或编辑器内容与已接受版本不同，不能按旧行号跳到无关正文；此时应使用现有 Markdown 编辑器显示标明“上一次成功加载的讲解”的只读内容。它只在当前阅读期间使用，不写磁盘、不覆盖原文件，不另建独立阅读面板。

执行“行内代码讲解：停止讲解”后，应清除正文、额外高亮和导航，保留代码页与阅读进度。下次主动打开同一项目中的同一讲解时，恢复有效步骤并重新检查代码；打开其他项目、其他讲解文件或其他讲解标识时，不混用进度。重启 VS Code 不自动开始讲解，必须主动打开文件。

## 让外部 agent 为自己的项目生成讲解

把本项目的 [Markdown 文件约定](../.scratch/first-release/explanation-format.md)交给外部 agent，并指定代码项目、需要讲解的调用或修改以及输出 `.md` 的位置。要求它读取实际代码，使用完整提交标识，按实际内容计算整文件与范围摘要；保留已有讲解和步骤的标识，不能照抄演示工程中的路径、提交或摘要。

可确认的 JavaScript 格式变化需要生成端同时填写引用和目标的 `formattingSha256`。从代码项目目录运行 `node <插件项目路径>/tools/code-reference.cjs src/example.js 4 5` 可生成实际引用和目标；先构建插件。`--stdin` 可接收外部工具实际取得的编辑器文本，默认只读磁盘，不能假定它包含未保存修改。生成器使用同一份完整解析结果计算范围，不自行去掉源码里的所有空格。完整格式示例见 [JavaScript 讲解示例](../.scratch/first-release/explanation-formatting.example.md)。

插件不调用模型，也不提供录制或编写界面。正文代码块只用于阅读，不执行脚本、不插入源码；不支持 `.tour`，也不读取独立 HTML 文件。普通 Markdown 链接仅作为链接显示，正文不会获得执行 VS Code 命令或改写源码的权限。

讲解不额外保存源码，不能恢复已经丢失的未提交代码。目标文本仍一致，只能说明本段文字对应，不能证明它依赖的其他代码或整份业务说明已经重新核对正确。

按[首版规格中的 26 项手动验收](../.scratch/first-release/spec.md)逐项操作，记录实际结果与必要截图。已有任务 01 的证据只证明当时最小扩展的显示能力；正式文件读取、更新、对应检查和进度一起使用的结果，需要实际操作后再标为通过。需要确认源码未改动时，对照演示记录的 HEAD、Git 状态、暂存区和磁盘摘要；编辑器的未保存状态另行记录。
