# 讲解侧栏、JSON 文件与行内复制规格

Status: ready-for-agent

2026-10-22，根据本轮 `grill-with-docs` 的 12 项回答整理。请求者最初要求只发布规格，随后授权安排子代理用 `$implement` 完成任务。本文是 0.2.0 的实现要求；实际通过范围见[任务记录](issues/README.md)，不能用旧 0.1.3 结果替代本轮验证。

## 问题

阅读者已经认可代码旁的讲解和代码区域的划分，但重新打开讲解仍需反复寻找文件、输入路径。现有插件只记住文件内的步骤，没有可直接使用的最近讲解入口，也没有项目讲解列表。

现有 Markdown 文件同时包含正文和大量定位备注。阅读者不需要脱离插件阅读，愿意改用 JSON 保存结构、Markdown 保存步骤正文。现有代码框通过矢量图显示，不能拖选文字；进入原 Markdown 才能复制过于麻烦。

## 解决方式

在 VS Code 左侧活动栏提供插件图标，点击打开讲解侧栏。侧栏提供“继续上次讲解”、最近打开列表和项目讲解列表；讲解可展开步骤。点击标题恢复进度，点击步骤直接阅读对应位置，展开列表本身不开始讲解。

新讲解统一使用 JSON，默认放在项目根目录的 `.code-explanations/`，允许通过项目设置更换目录，并保留选择其他位置文件的入口。已有 Markdown 讲解由 agent 一次性转换，插件不提供导入或旧格式阅读能力。

有效步骤继续在真实代码或 diff 旁显示。代码以可选择的文字呈现，支持拖选复制和整块复制；为此允许适度简化边框、圆角和留白。代码区域与下面的简短中文翻译仍须明显分开。“查看正文”打开排版后的阅读页面，默认定位当前步骤，不要求阅读 JSON。

## 使用需求

1. 作为阅读者，我希望点击左侧插件图标就能找到讲解，以便无需反复寻找命令。
2. 作为阅读者，我希望侧栏列出当前项目的讲解，以便无需记忆文件路径。
3. 作为阅读者，我希望看到讲解标题和必要的路径区别，以便分清同名讲解。
4. 作为阅读者，我希望有“继续上次讲解”，以便接着上次的步骤阅读。
5. 作为阅读者，我希望有最近打开列表，以便找回目录之外打开过的讲解。
6. 作为阅读者，我希望最近讲解和进度按项目区分，以便不混用不同项目的记录。
7. 作为阅读者，我希望重启后仍能主动恢复进度，以便分多次阅读。
8. 作为阅读者，我希望启动项目和展开列表都不自动开始讲解，以便自行决定何时阅读。
9. 作为阅读者，我希望展开讲解查看步骤标题，以便直接寻找感兴趣的代码。
10. 作为阅读者，我希望点击步骤直接跳转，以便不用从第一步连续前进。
11. 作为阅读者，我希望侧栏标明当前步骤和进度，以便知道自己读到哪里。
12. 作为阅读者，我希望侧栏跳转与现有上一步、下一步保持一致，以便使用任一入口都不会丢失位置。
13. 作为阅读者，我希望新讲解保存后出现在列表，以便不必重新选择目录。
14. 作为阅读者，我希望列表更新不打断当前阅读，以便 agent 保存其他讲解时不会抢走位置。
15. 作为阅读者，我希望能改变项目的讲解目录，以便适应现有项目布局。
16. 作为阅读者，我希望仍能手动打开其他位置的讲解，以便使用临时讲解。
17. 作为阅读者，我希望文件缺失或格式错误时明确说明对象和原因，以便知道需要恢复文件还是修正内容。
18. 作为阅读者，我希望直接拖选代码中的字符或几行，以便只复制需要的部分。
19. 作为阅读者，我希望一次复制整个代码块，以便保留该段代码的缩进与换行。
20. 作为阅读者，我希望普通文件和 diff 讲解都支持复制，以便不用离开当前阅读位置。
21. 作为阅读者，我希望复制得到代码原文，以便不会混入行号、按钮、说明文字或用于排版的字符。
22. 作为阅读者，我希望复制不会改动源码或编辑器的未保存内容，以便继续正常工作。
23. 作为阅读者，我希望代码和简短翻译仍明显分开，以便顺着真实执行过程阅读。
24. 作为阅读者，我希望“查看正文”显示排版后的完整讲解，并定位当前步骤，以便回看上下文。
25. 作为阅读者，我希望无法定位代码的步骤仍能阅读正文，以便一个失效步骤不妨碍理解其他内容。
26. 作为生成讲解的 agent，我希望在一个 JSON 文件中记录结构及 Markdown 正文，以便不必同步多份配套文件。
27. 作为生成讲解的 agent，我希望更新时保留讲解和步骤标识，以便正文修改或步骤重排不会重置阅读位置。
28. 作为生成讲解的 agent，我希望继续使用已有代码引用和检查规则，以便换格式不会放宽代码对应要求。
29. 作为维护者，我希望旧讲解只做一次转换，以便插件不长期维护两种阅读格式。
30. 作为请求者，我希望真实界面验证在独立后台 VS Code 中进行，以便不切换或操作我正在使用的窗口。

## 实现决定

### 现有要求与本轮变化

- 本轮替换首版中手动选择 Markdown、禁止目录扫描、原 Markdown 正文入口及代码框使用图片的相关决定。其余代码检查、diff、自动更新、只读源码与停止清理要求继续适用。
- 不要求独立 Markdown 工具直接阅读讲解；步骤正文继续使用 Markdown，不改成独立 HTML 文件，也不获得执行作者脚本的能力。
- 讲解仍按执行顺序简短翻译对象、动作、条件与结果，不扩展为通用语法课程。可调整外框，不因此改变已确认的文字标准。

### 侧栏与目录

- 在左侧活动栏提供独立插件图标及讲解侧栏。图标应能表达代码讲解用途，适应深浅主题；不将状态栏常驻入口作为主要打开方式。
- 侧栏包含“继续上次讲解”、最近打开和项目讲解。项目列表从配置的讲解目录读取；同一文件在同一列表中不重复出现，不按标题合并不同文件。
- 默认目录为项目根目录下的 `.code-explanations/`，可在项目设置中更改。目录不存在时显示空状态和实际目录，不能冒充读取失败，也不因展开侧栏自动创建目录或讲解文件。
- 项目列表只检查指定目录及其子目录中的 JSON 文件，不扫描整个项目寻找讲解；目录设置变化后重新读取相应列表，解除旧目录的订阅。
- 新增、修改或删除讲解文件后更新列表；不自动开始新讲解、不切换当前步骤。已打开讲解自身的保存仍按现有更新规则处理。
- 保留选择其他位置 JSON 文件的操作。这些文件成功打开后出现在对应项目的最近列表中，不复制进默认目录。
- 多项目工作区按项目区分目录、最近记录及进度；手动打开外部讲解时明确其代码所属项目，不按文件位置猜测代码根目录。
- 没有项目时提示先打开项目；目录不可读时说明具体目录及失败原因。无效讲解显示文件名和错误状态，不编造标题、步骤或进度；其他文件仍可使用。

### 选择、进度和更新

- 单纯展开讲解读取并列出步骤，不激活阅读。点击讲解标题恢复该讲解保存的步骤，首次打开从第一步开始；点击某个步骤则以该步骤作为本次明确选择。
- 成功接受讲解后才替换当前阅读并记入最近列表。取消选择、读取失败或结构无效时保留原有有效阅读，不能把失败文件记为“继续上次讲解”。
- 最近记录按成功主动打开的时间排序，按文件位置去重并有数量上限；具体上限由实现确定。标题及数量可从文件重读，不把正文、源码或定位结果持久保存进最近记录。
- 按项目、讲解文件位置和讲解标识保存步骤标识。重排按标识保持步骤，步骤被删除则回第一步，讲解标识变化视为新讲解。
- 列表展示、文件发现与开始阅读分开。重启后可以列出文件及恢复入口，但不能创建行内讲解、打开代码页或开始上次阅读，直到用户主动选择。
- 继续入口指向的文件已缺失或不可读时说明具体文件，不静默打开其他讲解。可继续选择其他列表项；不因一次读取失败删除仍可能恢复的文件或进度。
- 侧栏只显示现有阅读流程管理的当前讲解和步骤，不另存一套活动阅读状态。现有导航、侧栏、正文入口与停止操作使用同一份选择结果。
- 连续点击步骤、保存讲解、切换文件、关闭正文页与停止时，旧读取不能覆盖最新选择；停止后不能因列表刷新或迟到结果重新显示正文。
- 停止阅读后清除讲解和代码突出显示，解除当前阅读所持资源；侧栏列表与已保存进度保留，代码页保持打开。

### JSON 与一次性转换

- 后续阅读只接受新的 JSON 讲解。文件中包含格式版本、稳定讲解标识、标题、代码引用以及有序步骤；步骤包含稳定标识、标题、Markdown 正文及普通文件或 diff 定位。详细约定见配套格式文档。
- 保持现有项目路径、Git 固定版本、空白一侧、范围摘要及 JavaScript 格式摘要的含义；不因 JSON 的引入放宽检查，也不保存额外源码副本。
- JSON 完整结构通过检查后才替换当前内容。半次保存、未知版本、重复字段、重复步骤标识及无效引用不能替换上一次成功加载的讲解。
- 读取端、外部 agent 的生成及检查工具、讲解 skill 和示例必须使用同一格式约定，实施时一并调整。
- 既有讲解由 agent 一次性转换为新 JSON，并放入相应项目的约定目录；保留讲解和步骤标识、顺序、正文、引用、摘要与固定提交。转换不是重新计算摘要或修正失效代码的授权。
- 一次性转换需记录旧文件和新文件的对应关系、结构检查及代码对应结果，原文件保留，不静默覆盖其他讲解。插件不提供“导入旧讲解”，也不在正常阅读流程中保留旧 Markdown 解析。
- 讲解标识保留不等于位置变更后自动继承旧进度。沿用首版边界：跨文件位置、项目位置及本次换文件格式的旧进度迁移不作保证；新 JSON 成功打开后必须满足本轮的记忆和恢复要求。

### 行内文字与复制

- 有效普通步骤显示在对应代码旁，diff 步骤显示在真实比较的目标侧；只保留当前一步的一份正文。仍验证删除行、新增行、双侧目标和步骤跳转，不能用独立阅读页或侧栏正文替代行内验收。
- 行内代码必须是真实可选择的文字，支持鼠标拖选部分内容并使用普通复制操作。保留图片、只增加整段复制按钮或要求先进入“查看正文”，都不满足行内复制要求。
- 每个代码块提供整块复制操作。复制的是正文中该代码块的代码内容，不是 JSON 转义文本，也不是重新读取当前项目文件得到的另一段内容。
- 保留代码字符、缩进和换行，包括中文、引号、反斜杠、空行及长行。显示换行和语法高亮不能改变复制结果，不额外加入行号、语言标签、装饰空格、框线字符或说明文字。
- 优先满足行内阅读、拖选和整块复制。尽量保留清楚的代码区域和语法高亮；允许简化原先图片代码框的边框、圆角及留白，不要求与效果图逐像素一致。
- 简化外观后仍须明显区分代码和下面的说明，并在普通文件、窄 diff、深浅主题中实际检查，不能退回代码与正文混在一起的显示。
- 复制操作只使用当前有效显示所对应的代码块，不为作者正文开放任意命令或脚本执行。切换步骤、替换讲解、更新正文或停止后，旧操作不能误复制其他步骤的内容。
- 不修改 VS Code 安装文件、用户主题或全局设置来实现样式；不依赖对用户当前窗口的输入或操控。

### 查看正文

- “查看正文”提供排版后的完整讲解，默认定位当前步骤，代码同样可拖选和整块复制。显示标题、正文及必要的代码对应提示，不把原始 JSON 字段和转义串当作阅读内容。
- 正文页是当前阅读的辅助入口，不另存当前讲解或源码，也不替代有效步骤的行内显示。实际只读阅读页面采用何种现有显示接口，由实施时选择并验证。
- 当前步骤无法确认代码位置时清除该步行内显示和突出显示，说明失败原因，并允许在正文页阅读；不能在旧位置保留讲解。
- 使用上一次成功加载的讲解时明确标注，正文入口必须来自该份内容，不拼入未通过检查的新文件。文件恢复后按成功加载的内容更新。
- 正文页更新、替换和关闭沿用阅读流程的生命周期；停止后不继续持有已经释放的活动正文，也不执行迟到的更新。

## 验证

### 当前事实与实施顺序

0.1.3 的历史检查只证明旧 Markdown 与图片代码框流程，不证明本规格通过。各项新行为的完成情况以本轮任务和实际结果为准。

实施时先在独立后台 VS Code 验证可选择文字在普通代码、diff 和正文页中的显示与复制。允许按本轮决定简化外框，但不降低行内位置与复制要求；界面方案通过后再完成侧栏、JSON 及转换的整体接通。

| 19 | 快速选择不同步骤、切换讲解、保存并停止 | 只有最后有效选择可显示或复制；停止后无旧结果重新出现 |
| 20 | 转换既有讲解，并以新 JSON 打开 | 标识、顺序、正文和引用未被篡改；新格式检查及实际定位结果均有记录，旧文件保留 |
| 21 | 在新版本尝试把旧 Markdown 作为讲解打开 | 明确说明需要转换；不进入旧格式阅读，不提供插件导入功能 |
| 22 | 全程检查源文件、Git 状态及独立桌面记录 | 没有保存或改写源码、切换 Git 状态、操作或切换用户窗口 |

### 现有检查与必要自动验证

- 后续实施需运行实际类型检查、构建、打包及相关已有检查。维护因格式变化受影响的原检查，只替换旧 Markdown 或图片呈现已经被本规格废止的断言，不删除仍需保留的代码检查、取消和顺序场景。
- 请求者已要求减少人工操作，因此沿用独立 Windows 桌面、独立 VS Code 配置、扩展目录与案例工程。后台验证不向当前桌面发送输入，不激活或切换用户窗口；记录进程、隔离情况、实际安装包及截图。
- 截图只能证明显示，不能证明复制。必须在测试实例中实际选择文字、执行复制并读取相应剪贴板结果；只解析 HTML、取得节点文字或调用整块复制接口，不能替代普通拖选复制的验证。
- 若实际复制会影响用户桌面的剪贴板，应先采用可隔离的验证方式；不能做到时明确记录未验证范围，不能借后台验证覆盖用户剪贴板后声称没有影响。
- 继续使用已有可控制读取完成顺序的检查，覆盖侧栏跳转、连续保存、替换讲解、正文操作与停止的交错。这些顺序难以通过人工点击稳定重现，只增加当前入口确实缺失的场景。
- 跨进程进度使用测试实例的真实持久存储验证，不能用扩展测试模式的内存结果代替。必要的 JSON 结构及转换比较沿用正式解析入口和实际数据，不建立第二套生产阅读流程。

## 不包含的内容

- 不操作请求者的窗口；实现及验证使用独立后台 VS Code。讲解和 skill 的转换属于随后已授权的实施任务。
- 插件内模型调用、生成或编辑讲解、录制、插入或执行代码、自动保存源码。
- 正常阅读旧 Markdown、兼容 CodeTour、插件内旧文件导入、独立 HTML 讲解文件。
- 启动时自动开始讲解、发现新文件后自动抢占阅读、同时活动的多份讲解。
- 保存完整源码副本、放宽原有代码对应检查、重新定义 Git 比较或扩大语言格式容错范围。
- 跨项目或文件位置变化的历史进度迁移、云端同步、项目外自动扫描。
- 修改 VS Code 安装、用户主题或全局设置；仅用侧栏或独立正文页替代行内讲解。
- 推送仓库、发布插件或将待验证的方案记录为已通过。
