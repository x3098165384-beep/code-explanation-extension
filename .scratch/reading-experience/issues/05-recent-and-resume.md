# 05：继续上次讲解与最近打开记录

Status: ready-for-agent

执行情况：未开始。

## 要完成的行为

阅读者在侧栏点击“继续上次讲解”或最近打开的讲解，即可恢复正确文件和步骤。重启后记录仍在，但启动项目不会自动开始讲解；不同项目的记录互不混用。

Blocked by: 04（侧栏列出项目讲解并跳转步骤）

## 验收要求

- [ ] 侧栏提供各项目的“继续上次讲解”及最近打开列表，和项目目录列表同时存在；目录外成功打开过的讲解也能再次打开，无需输入路径。
- [ ] 仅成功主动打开并接受的讲解成为继续目标并进入最近列表；按时间排序、按文件位置去重、数量有上限，记录所采用的具体上限。
- [ ] 取消选择、无效 JSON、读取失败、只展开或发现文件不更新最近目标，不覆盖原有效阅读。失效继续入口说明具体文件，不猜测或静默打开其他讲解。
- [ ] 项目、讲解文件位置、讲解标识和步骤标识共同区分进度；使用最新文件重新检查引用后显示，不能复用上次代码位置或正文。
- [ ] 标题点击恢复进度，步骤点击使用本次明确选择；正文保存、重排或删除当前步骤的恢复结果符合规格，标题变化不被当成另一个步骤标识。
- [ ] 最近记录不持久保存正文、源码副本、旧位置或无后续用途的完整对象；侧栏只读取阅读流程的活动状态。
- [ ] 以同一独立用户配置关闭并重启普通 VS Code 测试实例，记录及步骤真实跨进程保留；启动不自动打开代码或开始讲解，主动点击后恢复。
- [ ] 两项目及多根目录工作区的目录、最近记录和进度互不混用；缺失文件不因一次失败删除原文件或可恢复记录。
- [ ] 停止后仍保留继续入口和步骤记录，重开仍有效；连续点击不同文件、更新列表和停止的迟到结果不能覆盖最新目标。
- [ ] 保存真实磁盘持久结果、重启阶段截图及逐项结果，确认不是用官方扩展测试模式的内存存储或人为预置记录冒充首次保存成功。
- [ ] 相关已有类型、构建及顺序检查通过；仅为实际新增的打开与持久保存交错补必要检查，说明人工难以固定顺序的原因。

## 验证方式与边界

使用任务 04 可操作的侧栏和任务 02 正式阅读入口，通过多个独立进程完成保存、同项目恢复和另项目隔离，不替换生产持久存储对象。项目或讲解路径改变后的旧进度迁移，包括一次性换格式的进度，不在本任务保证范围。
