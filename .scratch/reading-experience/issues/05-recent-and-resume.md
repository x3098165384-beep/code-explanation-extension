## 要完成的行为

阅读者在侧栏点击“继续上次讲解”或最近打开的讲解，即可恢复正确文件和步骤。重启后记录仍在，但启动项目不会自动开始讲解；不同项目的记录互不混用。

Blocked by: 04（侧栏列出项目讲解并跳转步骤）

## 验收要求

- [x] 侧栏提供各项目的“继续上次讲解”及最近打开列表，和项目目录列表同时存在；目录外成功打开过的讲解也能再次打开，无需输入路径。
- [x] 仅成功主动打开并接受的讲解成为继续目标并进入最近列表；按时间排序、按文件位置去重、数量有上限，记录所采用的具体上限。
- [x] 取消选择、无效 JSON、读取失败、只展开或发现文件不更新最近目标，不覆盖原有效阅读。失效继续入口说明具体文件，不猜测或静默打开其他讲解。
- [x] 项目、讲解文件位置、讲解标识和步骤标识共同区分进度；使用最新文件重新检查引用后显示，不能复用上次代码位置或正文。
- [x] 标题点击恢复进度，步骤点击使用本次明确选择；正文保存、重排或删除当前步骤的恢复结果符合规格，标题变化不被当成另一个步骤标识。
- [x] 最近记录不持久保存正文、源码副本、旧位置或无后续用途的完整对象；侧栏只读取阅读流程的活动状态。
- [x] 以同一独立用户配置关闭并重启普通 VS Code 测试实例，记录及步骤真实跨进程保留；启动不自动打开代码或开始讲解，主动点击后恢复。
- [x] 两项目及多根目录工作区的目录、最近记录和进度互不混用；缺失文件不因一次失败删除原文件或可恢复记录。
- [x] 停止后仍保留继续入口和步骤记录，重开仍有效；连续点击不同文件、更新列表和停止的迟到结果不能覆盖最新目标。
- [x] 保存真实磁盘持久结果、重启阶段截图及逐项结果，确认不是用官方扩展测试模式的内存存储或人为预置记录冒充首次保存成功。
- [x] 相关已有类型、构建及顺序检查通过；仅为实际新增的打开与持久保存交错补必要检查，说明人工难以固定顺序的原因。

## Comments

Reader 沿用现有全局 Memento 保存进度，并按项目 URI 保存最多 20 个最近成功接受的文件 URI。数组按最近打开顺序排列，按文件位置去重；不保存标题、正文、源码或旧定位。成功接受新讲解后才更新记录，文件发现、刷新、取消、失败和停止不更新最近目标。

每个项目的侧栏同时提供“继续上次讲解”、“最近打开”和“项目讲解”。标题及步骤从最新合法文件读取；目录外最近文件由目录列表的管理者订阅，配置变化和停用时解除订阅。缺失文件仍保留记录，点击时显示具体文件的读取错误。

已补充可控制读取顺序的检查，确认先点击的文件迟到时不会进入最近列表或覆盖继续目标；这种读取顺序难以人工稳定制造。
