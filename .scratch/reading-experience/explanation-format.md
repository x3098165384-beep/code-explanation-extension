# JSON 讲解文件格式

本文件配合[讲解侧栏、JSON 文件与行内复制规格](spec.md)，为后续实施明确文件约定。2026-10-22 仅发布规格；0.1.3 尚不能读取此格式。下列字段及版本号是对已确认 JSON 方向的具体约定，不表示插件已实现或案例已转换。

## 文件与版本

- 一份讲解使用一个 UTF-8 `.json` 文件，支持文件开头的 UTF-8 BOM 和 LF、CRLF 换行。默认位于项目的 `.code-explanations/`，文件名由讲解内容确定，不用于充当稳定标识。
- 顶层为单个 JSON 对象，`version` 固定为整数 `2`，明确区别于旧 Markdown 封装中的版本 `1`。不支持的版本应说明，不能按相似字段猜测读取。
- 使用严格 JSON，不允许注释、尾随逗号、重复字段或未声明字段。正文中的引号、反斜杠和换行按 JSON 字符串规则转义；读取后还原成 Markdown，不把转义符直接显示给阅读者。
- 不再使用 HTML 备注或 Markdown 一二级标题来识别讲解结构；正文内同名标题或旧备注只属于正文，不创建新步骤。

## 顶层字段

| 字段 | 要求 |
| --- | --- |
| `version` | 必填，整数 `2` |
| `id` | 必填，非空字符串；同一讲解更新或转换时保留 |
| `title` | 必填，非空字符串；侧栏及阅读界面的讲解标题 |
| `description` | 可选，Markdown 字符串；对应原文件讲解标题之后、第一步之前的简介，缺省为空 |
| `sources` | 必填对象；属性名为本文件内唯一代码引用名称，属性值按下面的引用规则填写 |
| `steps` | 必填的非空数组；数组顺序就是阅读顺序，不另外保存排序表 |

`id` 不使用标题、路径、步骤编号或正文摘要。标题和正文可变，标识保持稳定。文件中不保存最近打开时间、当前步骤或用户配置，这些由 VS Code 的本地记录管理。

## 每步共有字段

| 字段 | 要求 |
| --- | --- |
| `id` | 必填，非空字符串，在整份讲解中唯一 |
| `title` | 必填，非空字符串，用于步骤列表和正文标题 |
| `body` | 必填，非空 Markdown 字符串，保存简短代码翻译及必要代码块 |
| `kind` | 必填，`file` 或 `diff`，分别使用下列对应字段 |

Markdown 正文支持原有段落、标题、列表、行内代码、粗体、代码块和普通链接。作者原始 HTML 按文字处理；正文不获得执行脚本、任意命令或插入源码的能力。内部生成的整块复制操作不能依赖对作者正文的全面信任。

代码块仍使用普通 Markdown 围栏或缩进写法，语言名称用于显示高亮。不嵌入矢量代码图片替代文字，不为排版加入会污染复制的字符。正文中的局部源码举例不构成另存完整源码的要求；代码检查仍以 `sources` 和目标摘要为准。

## 普通脚本步骤

除共有字段外，只填写：

| 字段 | 要求 |
| --- | --- |
| `source` | 必填，引用 `sources` 中预期存在的一个代码引用 |
| `target` | 必填，一个连续代码范围 |

每步对应一个文件的连续范围，跨文件通过多个步骤组织。不填写 diff 专用字段。

## diff 步骤

除共有字段外，只填写：

| 字段 | 要求 |
| --- | --- |
| `comparison` | 必填，`commits` 或 `working-tree` |
| `left` | 必填，改前代码引用名称 |
| `right` | 必填，改后代码引用名称 |
| `targets` | 必填对象，仅允许 `left`、`right`，至少提供一侧的有效范围 |

两个固定提交的比较，两侧都使用同仓库的固定 Git 引用。未提交比较，左侧为生成讲解时的固定 HEAD，右侧为编辑器当前内容，包含未保存修改。两侧都要明确存在状态，不能都不存在；不存在侧不能有目标。

双侧范围全部确认后才显示双侧步骤。正文有改后目标时显示在改后侧，否则在改前侧；无论单侧还是双侧目标，都打开真实的完整 diff。不填写普通步骤的 `source` 或 `target` 字段。

## 代码引用与范围

继续使用旧格式中下列字段及其含义，不在 JSON 迁移时重新计算或降低检查条件：

| 对象 | 字段 |
| --- | --- |
| 当前项目文件 | `kind: workspace`、`path`、`exists`；存在时必填 `sha256`，符合原 JavaScript 规则时可有 `formattingSha256` |
| 固定 Git 文件 | `kind: git`、`path`、`commit`、`exists`；存在时必填 `sha256`，不使用 JavaScript 格式摘要 |
| 目标范围 | `startLine`、`endLine`、`sha256`；符合原 JavaScript 规则时可有 `formattingSha256` |

- 代码路径相对明确选择的项目根目录，使用 `/`，不接受绝对代码路径或越出项目的路径。讲解本身可从其他位置主动选择，但其代码引用仍属于所选项目。
- Git 使用完整的 40 或 64 位十六进制提交标识。摘要为 64 位小写十六进制 SHA-256；`exists: false` 时不填摘要，只用于确认整个新增或删除文件的空白一侧。
- 范围从第 1 行开始，包含结束行，必须为非空白的连续范围。仅对实际读取文本计算摘要，不保存目标源码副本或上次计算出的新位置。
- 文本规范化、固定版本严格核对、同文件同行数唯一匹配、双侧失败处理及 JavaScript 格式摘要算法，完整沿用[旧格式的代码引用、摘要及检查规则](../first-release/explanation-format.md)。只复用这些规则，不复用其中 Markdown 封装、版本号、文件扩展名或正文回看入口。
- 字符串、模板、正则、注释内部空白及增删换行、分号仍不因本次格式调整被放宽；未支持的语言不推断语义等价。

## 保存、错误与正文显示

- 整份结构合法才接受更新。结构错误与实际代码无法对应分开处理；具体步骤引用缺失或内容不符不能被视为空白文件，也不使其他合法步骤全部不可读。
- 未保存的讲解编辑不替换当前内容，已保存的 JSON 才参与更新；源码仍使用编辑器当前内容，包括未保存修改。
- 更新按稳定标识保持步骤，当前步骤被删除回第一步，讲解标识变化视为新讲解。无效保存保留上一次成功加载内容，仍重新检查当前源码；修复保存后自动更新。
- “查看正文”从已经接受的标题、简介和步骤生成可读内容，按步骤标识定位，不依赖 JSON 中的物理行号。不显示定位对象或转义字符串，不为回看另存一份磁盘 Markdown。
- 临时使用旧的已接受内容时明确标注“上一次成功加载的讲解”；第一次打开就失败时没有旧正文可展示。

## 一次性转换的检查清单

后续由 agent 转换，不在本次规格编写期间执行，也不增加插件导入入口。

1. 读取实际旧讲解，确认其结构；保留原文件，将新 JSON 写入所选项目的约定目录，写入前检查同名冲突。
2. 将旧标题、简介、按出现顺序组织的步骤转为显式字段，正文只做 JSON 字符串所需转义，不改写内容。
3. 讲解及步骤标识、代码引用名称、文件路径、固定提交、范围与摘要保持原值，仅将外层格式版本改为 `2`。失效代码按原错误报告，不能通过更新摘要掩盖失效。
4. 对比旧与新解码后的正文、步骤顺序及引用，确认没有遗漏；再使用新版本正式读取入口检查 JSON 结构和当前代码对应结果。
5. 记录转换前后文件位置及结果。文件路径改变时不声称旧进度会自动继承；转换后新文件的主动打开、进度保存和重启恢复按主规格验收。
