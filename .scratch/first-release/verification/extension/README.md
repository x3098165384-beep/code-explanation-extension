# 最小行内讲解验证扩展

只执行任务 01，使用硬编码的少量讲解和独立演示工程验证 VS Code 公开接口。这里没有正式的讲解文件读取器、录制功能、模型调用、自动更新或进度恢复。

先运行验证目录里的示例准备与启动工具，再在新打开的 Extension Development Host 中使用命令面板。扩展从相邻 `runtime` 目录读取准备工具生成的 `manifest.json`，不依赖窗口是否已经打开工作区目录。

1. 执行“行内讲解验证：准备未保存示例”。它只在独立示例的编辑器文档中把 `return total;` 改成 `return total + 1;`，不保存，并在修改后记录阅读前的基准。这个准备动作与后续只读的阅读动作分开。
2. 执行“行内讲解验证：开始”。普通脚本用于观察较长 Markdown、列表、粗体、代码块和普通链接。
3. 使用评论末尾的导航、底部状态栏或“选择步骤”命令，依次查看删除行、新增行、双侧对照、当前修改、整个新增文件、整个删除文件和无效提交。
4. 在每个场景实际观察并保存窗口截图。JSON 只记录实际标签页和编辑器的状态、目标范围及源码摘要，不能证明屏幕上每个元素都已正确显示。
5. 执行“行内讲解验证：停止”，观察正文和突出显示消失、代码页仍打开，检查记录中的 Git、磁盘和准备的未保存内容均未变化。

证据目录来自准备工具的约定，每次场景、手动记录和停止都生成 JSON，`latest.json` 是最近一次结果。普通阅读和跳转不修改源码，Git 历史通过只读内容提供器读取；只有明确的准备命令会制造本次验证需要的未保存示例。

语法检查可在本目录运行 `node --check extension.js`。此检查不能替代真实 VS Code 运行和截图验收。
