# 真实 VS Code 行内与 diff 验证

本目录只服务于首版任务 01。验证扩展使用少量固定案例检查公开显示接口，不是正式讲解播放器，不包含 Markdown 文件读取、自动更新、阅读进度或模型调用。

2026-10-21 已在 Windows x64、VS Code 1.142.0 中完成任务 01 的真实运行验收。截图、对应运行记录、通过项目和未验证的范围见[验证结果](results.md)。窗口由请求者手动操作，代理只在后台整理记录；本次没有安装自动化 MCP 工具。

## 准备和启动

需要本机已有 Node.js、Git 和 VS Code。验证不安装第三方依赖，不更改用户原有 VS Code 配置或扩展。

第一次启动，在本目录执行：

```powershell
.\launch-verification.ps1
```

启动工具会先建立独立 Git 演示工程，再用隔离的用户配置和扩展目录打开扩展开发窗口。只打开一个演示源文件，不把整个工程文件夹作为工作区；扩展直接读取已记录的演示工程位置。若 `code.cmd` 不在 PATH 中，通过 `-CodePath` 指定已安装的 `Code.exe`。启动工具没有关闭工作区信任；若仍出现安全提示，应先停止界面操作并检查启动方式，不自动接受。

如果只准备工程、不启动窗口：

```powershell
node .\prepare-fixture.js
```

已有运行数据时默认停止，不覆盖文件或记录。保留已有工程再次启动可执行：

```powershell
.\launch-verification.ps1 -Reuse
```

需要重做示例时，先停止原验证窗口，再自行移走 `runtime` 目录；工具不会递归删除或重建现有目录。

## 示例工程的内容

独立工程包含两个真实提交：改前的价格计算直接返回乘积；改后先检查数量，并把乘积保存到变量后返回。改前有旧文件，改后移除旧文件并增加新文件，用于验证整个新增和删除文件的空白一侧。

第二次提交后，价格条件增加负单价判断并暂存；随后增加 `checked` 乘法，形成另一处未暂存改动。VS Code 中的准备命令再修改返回语句但不保存，用于检查编辑器内容是否被正确用于比较。准备动作只作用于本目录生成的独立示例，不应在真实用户工程执行。

`runtime/manifest.json` 记录工程位置、两次真实提交、案例路径、目标行号及未保存修改的准备信息。`runtime/prepared-baseline.json` 记录准备后的 HEAD、暂存区条目、Git 状态和磁盘文件摘要；扩展还需要在准备未保存内容后记录阅读前状态，阅读和停止后再比较。

`runtime` 被忽略，不提交生成的 Git 元数据或隔离用户配置。实际截图和运行依据保存在 `evidence`，由执行验证的人记录通过、失败和未验证的结果。

## 观察要求

在真实 VS Code 中观察原生行内 Markdown、删除行、新增行、双侧目标、同一 diff 内的前后跳转，以及未提交内容。截图是显示结果的依据；程序记录的 URI 和范围只能辅助说明，不能独自证明正文实际出现在正确位置。

停止后检查正文和突出显示是否清除，代码页是否保留，以及 HEAD、暂存区、磁盘内容和未保存文档是否与阅读前相同。本目录不替代首版后续任务的完整实现或验收。
