# Markdown 讲解文件格式

本约定供外部 agent 生成首版讲解文件及插件读取时使用，配合[首版规格](spec.md)和[完整示例](explanation.example.md)。正式读取器已按此约定实现，实际验证状态见[首版实现记录](implementation-results.md)；格式本身不作为界面已经通过的证据。

## 一个文件包含什么

文件扩展名为 `.md`，使用 UTF-8，可有开头的 UTF-8 BOM；换行可以是 LF 或 CRLF。正文是普通 Markdown；不读取独立 HTML 文件。

文件开头有一段以 `<!-- code-explanation` 开始、以独占行 `-->` 结束的 HTML 备注，其中保存一个 JSON 对象。随后是唯一的一级标题，作为讲解名称，可有简介。

每一步以 `<!-- step` 开始、以独占行 `-->` 结束的备注声明一个 JSON 对象，紧接一个二级标题和 Markdown 正文。二级标题是步骤名称；正文到下一个步骤备注或文件末尾结束。步骤次序就是出现次序，不再在文件头重复列出步骤。

以上备注必须是 Markdown 顶层独立块。代码围栏、缩进代码块或引用块中的同样文本只是正文，不能被识别为步骤。普通正文中的二级标题也不另外创建步骤。文件头只能出现一次，至少有一个步骤；标题和每步正文都不能为空。备注中的 JSON 不允许注释、尾随逗号、重复属性或未知字段；字符串不能包含会提前结束 HTML 备注的 `-->`。

普通 Markdown 预览可隐藏备注并阅读正文。插件显示步骤正文时也不显示格式备注。插件不把正文中的 HTML、链接或代码块解释成可执行操作。格式备注只允许下面列出的字段。

## 文件头

| 字段 | 含义和限制 |
| --- | --- |
| `version` | 必填，整数 `1`；其他版本不按当前版本猜测读取 |
| `id` | 必填，非空字符串；标识这份讲解，正文更新时保持不变 |
| `sources` | 必填对象；属性名是该文件内唯一的代码引用名称，属性值按下面的引用约定填写 |

讲解和步骤的 `id` 只用于稳定识别，不能是标题、当前编号或自动从正文计算的值。新建不同讲解时生成新标识；修改同一讲解或重排步骤时保留原标识；确实删除再创建的新步骤使用新标识。

保存进度时使用所选项目根位置、讲解文件位置、讲解 `id` 和步骤 `id`。不把源码或上次定位结果写入进度。移动讲解文件或项目目录后的进度迁移不属于首版保证。

## 代码引用

讲解打开时选择已打开的项目根目录；只有一个时直接使用，多个时明确选择，不按讲解所在目录猜测。没有项目时提示先打开项目。路径相对这个项目根目录，使用 `/`；不接受绝对路径或越出所选项目的路径。Git 引用使用管理该项目文件的本地仓库，将项目相对路径正确换算为仓库内路径。

每个引用包含：

| 字段 | 含义和限制 |
| --- | --- |
| `kind` | 必填，`workspace` 表示编辑器当前文件，`git` 表示固定提交中的文件 |
| `path` | 必填，项目内的相对文件路径，不是 Git 对象地址或外部 URL |
| `exists` | 必填布尔值；生成讲解时该文件在对应一侧是否存在 |
| `commit` | 仅 `git` 必填；完整的十六进制提交标识，长度为 40 或 64，不写 `HEAD`、分支名、标签名或缩写 |
| `sha256` | `exists` 为 `true` 时必填，64 位小写十六进制；对应完整规范化文本的 SHA-256 摘要。`exists` 为 `false` 时不填写 |
| `formattingSha256` | 可选，64 位小写十六进制；仅存在的 `workspace` JavaScript 文件（`.js`、`.mjs`、`.cjs`）使用，按下方规则计算完整文件的格式检查摘要 |

`workspace` 读取编辑器正在管理的当前文档，包括未保存内容；没有打开文档时读取当前文件。不能忽略编辑器内容而用磁盘旧文件代替。外部 agent 只能读到磁盘内容时，应按自己实际读到的文本生成摘要；插件发现不一致后按对应检查处理，不能替 agent 假定编辑器没有未保存修改。

`git` 读取指定提交中的内容，不以当前编辑器文档代替，即使该提交刚好是当前 HEAD。实际提交或文件无法读取时是资源错误，不把它视为空文件。

`exists: false` 专用于整个文件新增或删除时的空白一侧。必须先确认对应 Git 提交存在且确实无该文件，或者当前编辑器和项目文件中确实无该文件，才显示空白一侧。对应该引用不能设置目标范围。普通脚本步骤不能引用不存在的文件。空文件与不存在的文件不同：存在的空文件仍写 `exists: true` 和空文本摘要，但没有可用的非空代码目标。

源码内容不嵌入备注，不要求额外配套源码文件。当前文件可以变动，因此其完整文件摘要是生成讲解时的比较依据，不是必须让整个文件永久不变的要求。

## 普通脚本步骤

| 字段 | 含义和限制 |
| --- | --- |
| `id` | 必填，整份讲解内唯一的非空字符串 |
| `kind` | 必填，固定为 `file` |
| `source` | 必填，引用文件头中一个代码引用名称；可引用当前文件或固定 Git 版本，但必须预期存在 |
| `target` | 必填，下面定义的目标范围 |

每个普通步骤对应一个文件内的连续范围。跨文件阅读通过多个步骤组织，不把任意多个文件塞进同一步。

## diff 步骤

| 字段 | 含义和限制 |
| --- | --- |
| `id` | 必填，整份讲解内唯一的非空字符串 |
| `kind` | 必填，固定为 `diff` |
| `comparison` | 必填，`commits` 表示两个固定提交，`working-tree` 表示最近提交与当前编辑内容 |
| `left` | 必填，改前侧代码引用名称 |
| `right` | 必填，改后侧代码引用名称 |
| `targets` | 必填对象；可以有 `left`、`right` 两个属性，至少有一个；每个属性值是对应一侧的目标范围 |

`commits` 的两侧都必须为同一仓库的 `git` 引用；`working-tree` 的左侧为 `git`，右侧为 `workspace`，两侧属于同一仓库。`working-tree` 的左侧提交必须是生成讲解时的 HEAD，读取时仍需确认 HEAD 未改变；不把已变化基准的旧讲解默认为当前未提交比较。

左、右路径可以不同，用于明确说明一次文件重命名后的版本位置；插件不自行搜索或推断重命名。两侧都要有可确认的版本及存在状态，不能两侧都不存在。只有存在的一侧能设置目标。

双侧目标必须全部有效，才显示该步行内正文。只有一个目标时也打开完整比较，在目标所在侧显示；不能因为只解释删除行就退回改前文件的普通编辑页。

## 目标范围和文本摘要

| 字段 | 含义和限制 |
| --- | --- |
| `startLine` | 必填，正整数，首行从 1 开始 |
| `endLine` | 必填，正整数，不小于 `startLine`，包含该行 |
| `sha256` | 必填，64 位小写十六进制，对应该范围的规范化文本，不是整文件摘要 |
| `formattingSha256` | 可选；仅对应引用已提供 `formattingSha256` 时允许，记录该范围的格式检查摘要；不替代原文 `sha256` |

范围包含整行，不按列裁剪。用于匹配的行数由起止行确定。正文可解释其中的具体名称或表达式；范围本身不能全部为空白。

摘要统一按以下方式计算：

1. 使用实际读取的 Unicode 文本；如果整个文档开头有一个 BOM 字符，去掉它。
2. 将 CRLF 和单独的 CR 换行为 LF；不移除缩进、不删除行尾空格、不做大小写或 Unicode 等价转换。
3. 整文件摘要对完整规范化文本的 UTF-8 字节计算 SHA-256，保留文件末尾实际存在的 LF。
4. 目标范围先在规范化文本中按 LF 分行，取包含起止行的全部行，以 LF 连接；不额外添加结束换行。再对该字符串的 UTF-8 字节计算 SHA-256。
5. 空白范围不作为定位目标；指纹一致也不能据此把讲解定位到任意空行。

原文摘要保留缩进与空格。缺少下面的可选摘要时，仍按原文检查；已有版本 1 讲解保持可读，无须改版本号。

### JavaScript 中可以确认的格式变化

2026-10-21 请求者根据真实验收反馈，将可确认不影响含义的格式变化纳入首版。使用 Acorn 8.15.0 解析完整 JavaScript：先按 module 解析，失败再按 script 解析；均使用 ECMAScript latest 和 hashbang 支持。两种解析都失败时不提供格式摘要。JSX、TypeScript 和其他扩展名不使用本规则。

生成端与读取端复用 `dist/code-formatting.js` 的 `javascriptFormatting(text)`。输入先按原文规则规范化。解析收集代码符号和注释，按起点排序；EOF 不作为符号。每项记录种类（代码符号用 Acorn token.type.label，注释用 `Line` 或 `Block`）与输入原文，符号内部字符全部保留。相邻项前后间隙只移除 ASCII 空格与 Tab，保留全部换行和其他字符。按顺序组成 `[间隙, 种类, 原文]` 数组，末项为 `[末尾间隙]`，对 `JSON.stringify` 的 UTF-8 文本计算 SHA-256。

完整文件和范围使用同一规则。范围仍包含整行且行数不变，从完整文件的解析结果取完全位于范围内的符号及注释，再对范围内间隙计算；范围边界切开多行字面值或注释时不提供范围格式摘要。生成器不单独解析范围，避免把除法误当正则或丢失模板上下文。

只有当前完整文件的格式摘要与记录一致，才使用目标格式摘要寻找位置。因此不放宽字符串、正则、模板文本、注释内部空格，不忽略换行或增删分号，也不允许同时改掉文件其他代码后仍按格式匹配。只有水平空白变化及原文严格匹配的迁移得到支持；此规则不是语义相似搜索，也不能证明讲解含义已全部复核。

完整可读示例见 [JavaScript 格式讲解示例](explanation-formatting.example.md)，其中引用与目标均包含按实际文件生成的摘要。先构建插件，再从代码项目目录执行 `node <插件项目路径>/tools/code-reference.cjs src/example.js 4 5`，可只读实际文本并输出完整引用及目标；加 `--stdin` 则从标准输入读取外部工具实际取得的未保存文本，不假定磁盘等于编辑器。工具不自行连接编辑器，也不保存输入文本。

## 对应检查的顺序

1. 解析引用，确认项目、版本及文件存在状态；缺失则说明具体对象。不以其他版本、磁盘旧内容或其他路径补上。
2. 对固定 Git 内容，先核对完整文件摘要，再核对记录范围。固定版本的摘要或范围不一致说明文件约定与引用内容不一致，该步骤无效，不猜测另一个提交。
3. 对当前文件，完整文件摘要未变时核对记录范围；若范围不符合摘要，提示定位信息与代码不一致，不假装是行号移动。
4. 当前文件完整摘要已变化时，在同一个当前文档中检查所有同行数范围，找目标摘要的匹配位置。只在恰好一个位置匹配时重新定位，即使原行号处仍匹配，也必须排除另有匹配的位置。
5. 当前 JavaScript 引用与目标均有格式摘要，且当前整文件格式摘要一致时，改为核对所有同行数候选的格式摘要，原文相同及仅格式不同的位置一并计数。只有一个候选才继续；目标原文不同则提示“代码格式已变化，本段代码符号、字面值、注释及换行仍对应；讲解含义未重新核对”。条件不满足时沿用第 4 项的原文匹配。无匹配或多个匹配仍按无效步骤处理。
6. 双侧步骤检查两侧；任何一侧无效都不留下该步的行内正文。其他步骤仍能独立继续。
7. 显示前确认检查使用的文本仍是当前内容；文件编辑、外部重载或新读取结果取代原内容后，旧位置不得直接沿用。

完整文件摘要没有保存代码；范围摘要允许查找完全相同的内容，也不保存代码。若同一段代码依赖的其他方法已经变化，本检查无法证明原讲解的业务含义仍正确。因此不能把“文本仍对应”表述成“整份讲解已重新验证正确”。

## 更新与错误

结构错误包括：备注或 JSON 未完成、重复属性、未知格式或字段、缺少必要字段、重复步骤标识、引用名称未声明、起止行不是合法整数、摘要格式错误、缺少目标、标题或正文为空、步骤类型与两侧引用种类冲突。整份新文件通过结构检查前，不替换当前讲解。

运行时对应错误包括：文件不存在、版本无法读取、记录为不存在但实际存在、目标越界或内容不符、当前文件零个或多个匹配、未提交比较的 HEAD 已变化。结构有效的新讲解可以加载，这些错误只影响实际使用它们的步骤，不让整个文件变成不可读。

当前文件结构无效或暂时读不到时，保留当前已成功加载的正文和引用，不把未完成的新步骤混进其中。仍用当前源码检查原步骤。修复并保存后自动尝试加载；结构有效但具体步骤无效时，按该步骤的运行时错误处理。

讲解输入读取已保存的文件；未保存的讲解正文编辑不自动替换当前阅读。源码引用则读取编辑器当前内容，包括未保存的源码修改，两者不能混为同一个读取规则。

同一讲解更新后按步骤 `id` 保留位置，当前步骤被删除则回第一步；讲解 `id` 改变则视为另一份讲解。较早的文件读取结果不能覆盖较新的文件内容，停止后文件恢复也不能重新启动阅读。

无效步骤的正文入口回到该步骤在原 Markdown 中的二级标题。原文件无效、暂时无法打开或其编辑器内容已不同，当前又在使用上一次成功读取的内容时，不按旧行号跳到不相干的正文。此时用现有 Markdown 编辑器显示当前已成功加载内容的只读文档，明确标出“上一次成功加载的讲解”，仍能阅读该步正文。该文档只在当前阅读期间使用，不写入磁盘、不覆盖原文件，不另做独立阅读面板。文件恢复并成功读取后，重新确定原文件中的正文位置。

## 给外部 agent 的生成要求

- 使用真实项目及版本，按实际读取内容计算摘要；不要编造提交、路径、行号和摘要。
- 一个步骤说明一段实际代码，标题自然，正文按名称、条件和调用解释；不强制重复“情境、改前、改后、原因”等固定栏目。
- diff 中需要比较时说明改前、改后和原因；单侧步骤也明确保留完整比较的两侧引用。
- 更新正文时保留讲解和已有步骤的标识，不用重编号代替标识；真正新增步骤才生成新标识。
- 完整示例的路径、提交和摘要只适用于其演示工程。为用户项目生成时必须替换成真实值，不能照抄这些引用。
