# 07：下次主动打开讲解时恢复阅读进度

**要完成的行为：** 阅读者停止或退出后，下次主动打开同一份讲解能继续上次步骤；不同项目、文件和讲解的进度不混用，编辑器启动时不自动弹出讲解。

**Blocked by:** 02：打开 Markdown 并顺序阅读普通脚本讲解。

**Status:** ready-for-agent

**当前进展：** 功能已实现，本轮独立后台验收已完成。实际通过范围见[26 项验收记录](../../../docs/first-release-acceptance.md)和[后台验收说明](../../../docs/background-verification.md)。以下清单保留完整要求；未逐项确认的完整条件不提前勾选，已取得证据的场景无需重复手测。

依据：[首版规格](../spec.md)的验收 20、21、23，以及[Markdown 文件约定](../explanation-format.md)的进度识别方式。本任务可先用普通脚本完成全流程，之后按同一阅读状态适用于其他步骤类型。

- [ ] 按项目根位置、讲解文件位置、讲解标识和当前步骤标识保存必要进度；不保存源码、正文副本或上次计算的代码位置。
- [ ] 停止后重新主动打开同一份有效讲解，恢复上次步骤并重新执行代码检查；步骤不存在则回第一步，不用旧编号代替。
- [ ] 相同标题、相同步骤编号但不同项目、文件或讲解标识，不会错误套用另一份进度。首版不承诺移动文件或项目后的进度迁移。
- [ ] 启动或重新打开 VS Code 不自动开始讲解，不凭持久化数据恢复行内正文；只有用户主动打开才恢复步骤。
- [ ] 读到最后一步保留正文，用户停止后清除正文与突出显示，保留代码页及阅读进度；停用后没有旧读取重新出现。
- [ ] 打开另一份有效讲解时保存原进度，再进入新讲解的有效进度；取消选择或新文件无效时不破坏当前讲解和进度。
- [ ] 导航及保存进度使用同一个阅读状态管理者；不为方便持久化而另存当前步骤对象、源码引用或一份平行的活动讲解。
