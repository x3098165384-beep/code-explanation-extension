# 03：在固定 Git 版本间阅读单侧和双侧 diff 讲解

**要完成的行为：** 一份讲解能够穿插普通脚本与历史版本步骤，并在真实的两个提交比较中阅读删除行、新增行或双侧对照，不切换用户分支，也不把历史内容当成当前文件。

**Blocked by:** 02：打开 Markdown 并顺序阅读普通脚本讲解。

**Status:** ready-for-agent

**当前进展：** 功能与后台准备已完成，正式手动验收待确认。验收项在取得对应实际结果前保持未勾选。

依据：[首版规格](../spec.md)的验收 3、4、5、12、13、14、22、26；使用[Markdown 文件约定](../explanation-format.md)定义的固定提交引用、存在状态和双侧目标。

- [ ] 普通脚本步骤可以引用固定 Git 提交中的文件；即使该提交等于 HEAD，也按该提交读取，不改用编辑器里可能已修改的当前文件。
- [ ] diff 的两侧按同一仓库中两个完整提交标识读取，分别检查文件存在状态、整文件摘要和目标范围摘要；不检出文件、不切换分支、不修改暂存区。
- [ ] 删除行的正文及突出显示在改前侧，新增行在改后侧；双侧目标均有效时突出两侧，正文仅一处，优先位于改后侧。
- [ ] 只有一个目标的步骤仍打开完整 diff；同一比较内切换步骤保持对应 diff，不意外转成普通文件或累积重复正文。
- [ ] 普通当前文件、普通历史文件和固定提交 diff 可以按同一份讲解的顺序混合跳转，按引用区分同一路径的不同版本。
- [ ] 明确给出两侧不同文件路径时能读取对应版本，不自动推断或搜索重命名后的其他路径。
- [ ] 整个文件新增或删除时，只有确认提交存在且该文件确实不存在才显示空白一侧；不存在侧不得有目标，实际空文件不被当成不存在。
- [ ] 缺少提交、文件、错误存在状态或摘要不符时，相关步骤说明具体原因并回到 Markdown 正文；不借用当前文件或另一个版本，也不阻断其余有效步骤。
- [ ] 双侧步骤中一侧无效时，清除该步全部行内正文及突出显示，不把有效的另一侧当成双侧步骤仍然成立。
- [ ] 用户主动切换步骤、替换讲解或停止后，原先的 Git 读取结果不能把旧版本正文重新放回界面；停止保留代码页。
