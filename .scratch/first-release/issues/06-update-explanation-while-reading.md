# 06：agent 保存讲解后自动更新，并保留当前步骤

**要完成的行为：** 阅读者无需手动重新加载，agent 保存有效 Markdown 后即看到新内容，并继续停在同一步；保存未完成或文件暂时无法读取时，保留上一次成功加载的讲解并说明新内容未加载，修复后自动恢复。

**Blocked by:** 04：一起阅读已暂存、未暂存和未保存的修改；05：代码移动时重新定位，失效步骤仍能阅读正文。

**Status:** ready-for-agent

**当前进展：** 功能已实现，本轮独立后台验收已完成。实际通过范围见[26 项验收记录](../../../docs/first-release-acceptance.md)和[后台验收说明](../../../docs/background-verification.md)。以下清单保留完整要求；未逐项确认的完整条件不提前勾选，已取得证据的场景无需重复手测。

依据：[首版规格](../spec.md)的验收 15 至 19，以及必要自动化要求；按[Markdown 文件约定](../explanation-format.md)区分整份结构错误和单步对应错误。

- [ ] 只在当前讲解的已保存内容变化后自动读取；未保存的讲解正文不替换当前内容，源码仍按编辑器当前内容检查，不能混淆两种读取规则。
- [ ] 新文件整份结构检查通过后才替换当前讲解；重排、改标题或修改正文后按步骤标识保留位置，编号随新顺序更新。
- [ ] 当前步骤删除则回第一步；讲解标识变化视为另一份讲解，从第一步开始，不沿用相同编号或偶然相同的步骤标识。
- [ ] JSON 未完成、必要信息缺失、重复标识、未知版本、非法字段或文件暂时不可读时，不混入部分新步骤；保留当前已接受正文和引用，明确说明新内容尚未加载及原因。
- [ ] 新文件结构有效但某一步源码不对应时，接受文件更新，只让对应错误影响该步，不把它误当整份结构损坏。
- [ ] 保留的旧讲解继续检查最新源码；旧目标变动时不能因为正在保留旧正文而继续显示错误位置。
- [ ] 原 Markdown 损坏、消失或其编辑器内容已不同时，使用现有 Markdown 编辑器显示当前已接受内容的只读文档，明确写出“上一次成功加载的讲解”；不写磁盘、不覆盖原文件、不新增独立阅读面板。
- [ ] 文件修复并保存后自动更新，解除错误提示，重新确定原 Markdown 的正文入口。此前未成功打开过的无效文件仍不能凭空创建旧版本。
- [ ] 连续保存时，较早成功或失败的读取都不能覆盖较新内容、改变当前步骤或重新显示过期错误；切换步骤、替换讲解及停止后的旧结果同样不得重新显示。
- [ ] 替换、停止及扩展停用后，解除本次订阅并取消或忽略已失去用途的读取；文件后来修好也不自动重启已停止的讲解。

## 验证方式

手动依次修改正文、重排、删除当前步骤、改变讲解标识，保存并观察步骤位置。再保存不完整备注，修改源码，修好讲解并保存，确认旧正文的代码检查与自动恢复均正确。覆盖暂时不可读、无效文件首次打开和只读正文的情况。

需要少量可控制读取完成先后顺序的自动检查：让旧读取在新保存、步骤切换、另一份讲解打开或停止之后才完成，分别断言旧成功和旧失败都不能覆盖当前状态。原因是手动操作不能稳定制造这些完成顺序。沿用实际读取入口和生命周期，在测试中控制返回顺序，不为测试新增生产转发层、多份活动状态或独立调度框架。

运行实际构建及直接相关已有检查，记录控制先后顺序的检查结果；没有运行的案例明确标为未验证。
