# 04：一起阅读已暂存、未暂存和未保存的修改

**要完成的行为：** 阅读者可以在同一个 diff 中查看最近一次提交到当前编辑内容的全部改动，包含已暂存、未暂存及编辑器尚未保存的修改；生成讲解时的提交基准改变后会明确提示，而不悄悄改用另一份比较。

**Status:** ready-for-agent

**完成情况：** 已于 2026-10-22 完成。保留既有分诊标签；结果以本项验收勾选、下方证据及[首版验收记录](../../../docs/first-release-acceptance.md)为准。勾选结合实际运行、格式与顺序检查及对应实现检查，不表示任意输入组合或运行环境都已验证。

依据：[首版规格](../spec.md)的验收 6、7、13、24、26，以及[Markdown 文件约定](../explanation-format.md)的未提交比较规则。

- [x] 未提交比较的左侧是讲解生成时记录的完整 HEAD 提交，右侧是编辑器当前内容，不另做“仅已暂存”或“仅未暂存”的比较。
- [x] 在同一文件分别准备已暂存和未暂存修改，diff 能同时展示两部分，单侧和双侧目标均能使用已经提供的行内阅读及导航。
- [x] 编辑器中还有未保存源码时，右侧比较、位置检查和实际显示使用同一份当前内容；不读取磁盘旧版本冒充当前文件，也不为了校验而自动保存。
- [x] 当前编辑内容、磁盘重载或相关 Git 状态变化后重新确认当前步骤，不继续沿用旧位置；无法确认的步骤说明原因并保留其正文入口。
- [x] 新提交使 HEAD 不再等于讲解记录的提交时，相关未提交步骤提示基准已变化，需要更新讲解；不自动改写引用，也不把旧比较继续称为当前未提交修改。
- [x] 同一份讲解里的固定提交比较仍读取原来的提交，不因当前 HEAD 变化而随之改变或失效。
- [x] 整个新文件或删除文件的比较正确确认两侧存在状态，包含编辑器已创建但尚未保存的当前文件；缺失 Git 版本不能作为空白侧使用。
- [x] 混合当前文件、固定提交和未提交比较进行前后跳转，始终保持本步骤的正确版本与范围；不改动分支、暂存区或源码。
