# 05：代码移动时重新定位，失效步骤仍能阅读正文

**要完成的行为：** 源码位置变化后，讲解只有在能唯一确认对应内容时才继续出现在代码旁；内容变化、多个匹配或资源缺失时，说明原因并提供原 Markdown 正文，其他有效步骤照常继续。

**Blocked by:** 03：在固定 Git 版本间阅读单侧和双侧 diff 讲解。

**Status:** ready-for-agent

**完成情况：** 已于 2026-10-22 完成。保留既有分诊标签；结果以本项验收勾选、下方证据及[首版验收记录](../../../docs/first-release-acceptance.md)为准。勾选结合实际运行、格式与顺序检查及对应实现检查，不表示任意输入组合或运行环境都已验证。

依据：[首版规格](../spec.md)的验收 8 至 12、14，以及[Markdown 文件约定](../explanation-format.md)的文本规范化和对应检查顺序。未提交比较由任务 04 接入同一套对应检查，不在两个任务中复制匹配逻辑。

- [x] 文件未变化时核对记录范围；固定 Git 内容摘要不符时说明引用与内容不一致，不猜测另一个提交或另一份代码。
- [x] 当前文件已变化时，在同一当前文档中寻找同行数的唯一范围；默认严格匹配，带完整格式摘要的 JavaScript 允许已确认的水平空白变化。原文与格式候选统一排除重复，不跨文件或猜测语义。
- [x] 即使旧行号处仍然匹配，文件有变化后也要排除其他匹配位置；两个或更多匹配不能选第一个或偏信旧位置。
- [x] 只插入前面的无关行时能移动到新位置；带格式摘要的 JavaScript 分号前空格、Tab 和缩进变化可继续。代码符号、字面值、注释、换行变化或解析失败不做格式匹配；缺少摘要、固定 Git 和其他语言仍严格检查。删除、越界或全为空白不误挂讲解。
- [x] 文件其他位置已变化但目标唯一时仍能阅读，同时说明文件已有其他修改、本段文本仍一致；不能声称已重新验证整个业务说明。
- [x] 源码编辑、外部重载及资源状态变化会使当前步骤重新检查，不能等用户下次跳转才清除已经错误的正文和突出显示。
- [x] 无匹配、多匹配、文件缺失、版本无法读取及存在状态错误均给出具体对象和原因，不借用其他路径或版本；其他步骤独立判断。
- [x] 双侧步骤任一目标无法确认时，移除整步行内正文及突出显示；其正文仍能在原 Markdown 对应步骤阅读。
- [x] 正文入口按实际的步骤及其标题确定，不用已经过期的 Markdown 行号误跳。错误文件或位置提示清楚，不为无效步骤建设独立阅读面板。
- [x] 重新定位、再次检查、切换及停止所需引用由现有阅读和源码读取职责管理，不另存源码或维护一套旁路位置状态。显示只消费有效结果。
