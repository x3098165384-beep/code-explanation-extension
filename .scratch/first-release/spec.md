# VS Code 行内代码讲解插件首版规格

Status: ready-for-agent

2026-10-21 整理，2026-10-22 更新验收结果。依据[首版范围确认](../../docs/plans/first-release-scope.md)，使用[项目术语](../../GLOSSARY.md)。本文件发布在本项目的本地 Markdown 任务记录中。任务 01 已完成真实显示验证，见[运行记录](verification/results.md)。请求者随后授权完成任务 02 至 08；全部任务已实现并记录验收勾选，0.1.2 通过 45 项真实 VS Code 后台检查及 34 项格式与异步顺序检查，具体范围见[首版实现记录](implementation-results.md)。

## 问题

请求者希望在真实代码旁，按顺序阅读 agent 对代码名称、条件和调用的逐句说明，也希望在实际 diff 中理解改前、改后与原因。单独的长文档需要反复寻找代码；大表格和固定重复栏目又妨碍阅读。讲解必须独立保存，不修改被解释的源码。

## 解决方式

外部 agent 通过自己的 harness 读取代码，按约定生成一个 Markdown 讲解文件。插件只负责读取、校验、定位、显示和导航，不调用模型、不提供录制或编写界面。

一份讲解可以跨文件，并混合普通脚本步骤、最近一次提交与当前编辑内容的 diff 步骤、两个固定 Git 提交之间的 diff 步骤。每次只显示当前一步；步骤可以指出 diff 单侧或两侧的相关代码。源码来自现有编辑器文件或 Git 历史，不另存副本。

完整文件约定见[Markdown 讲解文件格式](explanation-format.md)。可直接检查结构的[完整讲解示例](explanation.example.md)同时包含普通脚本、两侧对照、删除行、新增行和未提交修改；其代码及版本背景见[示例说明](example-context.md)。示例使用独立演示工程，不引用本项目尚不存在的插件代码。

## 使用需求

1. 作为阅读者，我希望在代码行旁阅读解释，以便不在代码和长文档之间反复寻找位置。
2. 作为阅读者，我希望解释逐一对应代码名称、条件和调用，以便理解实际执行过程。
3. 作为阅读者，我希望阅读原本没有修改的普通脚本，以便了解一个方法或调用过程。
4. 作为阅读者，我希望查看两个 Git 提交之间的讲解，以便理解一次已经提交的修改。
5. 作为阅读者，我希望查看最近一次提交与当前文件的讲解，以便理解尚未提交的修改。
6. 作为阅读者，我希望已暂存和未暂存的修改一起比较，以便看到从最近一次提交至今的完整改动。
7. 作为阅读者，我希望当前编辑器中的未保存内容也参与检查，以便讲解不会指向已经改掉的代码。
8. 作为阅读者，我希望讲解不保存额外源码副本，以便直接使用项目文件和 Git 已有版本。
9. 作为阅读者，我希望一份讲解可以跨文件，以便从调用处跟到具体实现。
10. 作为阅读者，我希望普通脚本与 diff 步骤可以混合，以便围绕实际调用关系理解修改。
11. 作为阅读者，我希望一步 diff 讲解可以只指出删除行，以便阅读改前的逻辑。
12. 作为阅读者，我希望一步 diff 讲解可以只指出新增行，以便阅读改后的逻辑。
13. 作为阅读者，我希望同一步能够指出 diff 两侧，以便直接比较同一个条件或调用的变化。
14. 作为阅读者，我希望步骤切换时保持正确的 diff 比较，以便不会意外跳成普通文件。
15. 作为阅读者，我希望每次只看到当前一步，以便代码附近不会堆满讲解。
16. 作为阅读者，我希望使用上一步、下一步和步骤列表，以便顺序阅读或直接跳读。
17. 作为阅读者，我希望看到当前步骤编号和总数，以便知道阅读进度。
18. 作为阅读者，我希望代码只移动位置时仍能找到它，以便无关的行号变化不会让讲解全部失效。
19. 作为阅读者，我希望存在多个相同位置时明确提示，以便插件不会猜测并指错代码。
20. 作为阅读者，我希望代码已变化或资源缺失时不显示错误的行内讲解，以便不会把旧说明误认为当前代码的解释。
21. 作为阅读者，我希望无效步骤仍可在原 Markdown 中阅读，以便保留上下文。
22. 作为阅读者，我希望其他有效步骤仍可继续，以便一个错误不会中断整份讲解。
23. 作为阅读者，我希望主动选择 Markdown 文件开始讲解，以便可以使用任意指定位置的讲解文件。
24. 作为阅读者，我希望 agent 保存新讲解后自动更新，以便不必反复手动加载。
25. 作为阅读者，我希望更新或重排后仍停在同一步，以便阅读位置不被步骤编号变化打乱。
26. 作为阅读者，我希望当前步骤被删除后回到第一步，以便有确定的继续位置。
27. 作为阅读者，我希望无效更新不替换当前可读讲解，以便 agent 尚未完成的一次保存不会中断阅读。
28. 作为阅读者，我希望错误修复并保存后自动恢复更新，以便无需关闭重开。
29. 作为阅读者，我希望下次主动打开时恢复进度，以便分几次阅读较长的讲解。
30. 作为阅读者，我希望启动编辑器时不自动开始讲解，以便自行决定何时阅读。
31. 作为阅读者，我希望读完最后一步后仍能查看内容，以便继续对照代码。
32. 作为阅读者，我希望停止后移除讲解和突出显示，但保留代码页与进度，以便继续工作。
33. 作为生成讲解的 agent，我希望在一个 Markdown 文件中记录正文及定位信息，以便不必同步多个配套文件。
34. 作为生成讲解的 agent，我希望有明确的版本、位置、文本检查和步骤标识约定，以便生成可校验、可更新的文件。
35. 作为阅读者，我希望所有操作只读取源码及 Git 历史，以便分支、暂存区、文件内容和未保存状态不被插件改动。

## 实现决定

### 文件读取和职责

- 文件读取负责解析整份 Markdown、检查必要信息及重复标识，只有全部结构检查通过才交给阅读流程。步骤顺序来自正文中的出现顺序，不另存一份排序表。
- 源码读取负责使用编辑器已管理的当前文档，包含未保存内容；固定 Git 版本按提交读取，不切换分支、检出文件或改动暂存区。当前文件与历史内容不能混用。
- 对应检查负责把代码引用解析成有效位置或具体失败原因。显示流程只使用检查结果，不再保留另一份源码或重复实现匹配规则。
- 阅读流程管理当前讲解、当前步骤、必要的文件更新订阅和正在进行的读取。只有当前阅读确实需要的正文和引用信息保留在内存中；停止或替换讲解时解除不再使用的引用。
- 阅读进度只保存项目、讲解文件及讲解标识对应的步骤标识，不保存正文、源码副本或上次计算的代码位置。

### 代码引用和检查

- 普通脚本步骤引用当前项目文件或一个固定 Git 提交中的文件。
- 两个提交的 diff 使用两个完整提交标识。未提交修改的 diff 记录生成讲解时的完整 HEAD 提交，并使用编辑器当前内容作为改后侧；当前 HEAD 不再等于记录值时，该比较不能继续称为本次未提交修改，相关步骤提示需要更新讲解。
- 完整文件的文本摘要用于判断文件是否发生变化；每个引用范围另有文本摘要和行数，用于核对具体位置。摘要只用于比较文本，不保存源码，也不证明讲解的业务含义仍然正确。
- 文件内容未变时核对记录范围；当前文件有变化时，在同一个文件内寻找同行数的唯一范围。默认按原文摘要匹配；JavaScript 的 `.js`、`.mjs`、`.cjs` 当前文件可额外提供整文件及目标的 `formattingSha256`。只有完整文件能解析，代码符号、字面值、注释及符号之间的换行全部对应时，允许符号之间的空格、Tab 与缩进变化。字符串、模板文本、正则表达式、注释内部的空白不放宽；不接受增删换行、可选分号变化、JSX、TypeScript 或其他语言的格式推断。
- 允许格式变化时也检查同文件所有同行数候选，包含原文及仅格式不同的重复位置；只有一个匹配才继续，提示“代码格式已变化”，不声称业务讲解已重新核对。整文件的代码内容或换行也变化、解析失败、缺少新摘要时，仍使用原文检查。固定 Git 引用始终严格检查原文；不跨文件搜索、不猜测语义。
- 检查使用与最终显示相同的编辑器内容或 Git 内容。打开步骤、源码编辑或重新加载、文件及 Git 状态变化、讲解更新和重新打开时，均重新确认当前步骤所需引用。异步读取完成后，显示前还要确认结果仍属于当前阅读以及对应的内容。
- 不能唯一确认对应关系时，清除该步原有行内讲解和突出显示，说明失败对象及原因，打开原 Markdown 对应步骤。不能保留旧位置让人误以为仍然有效。
- 如果原讲解文件也暂时无法读取或已经损坏，无法可靠定位正文，则用现有 Markdown 编辑器显示当前已成功加载内容的只读文档，明确标出这是上一次成功加载的讲解。它只用于当前阅读，不保存到磁盘、不覆盖原文件，也不另做独立阅读面板；原文件恢复后回到原文件的正文入口。
- 两侧都有目标的步骤必须确认两侧，才能作为有效 diff 步骤显示；一侧失效时该步按无效步骤处理。其余步骤独立判断。
- 文件、Git 提交或 Git 文件内容缺失时不自动联网获取、不切换到其他版本、不借用当前文件；说明无法读取的对象后允许继续其他步骤。

### 行内显示和导航

- 同时只阅读一份讲解，显示当前一步的正文。打开另一份有效讲解后保存原进度并替换；取消选择或新文件结构无效时保留当前阅读。
- 普通步骤在目标代码旁显示正文并突出引用范围。diff 步骤打开实际的两份代码比较，两侧目标各自突出显示，正文只显示一处：有改后目标时放在改后侧，否则放在改前侧。
- 同一个比较中的步骤复用对应 diff，不因下一步或另一侧定位而退回普通文件。跨到其他比较或普通脚本时打开相应内容。
- 每次切换先移除上一处正文和突出显示，再显示新步骤；提供上一步、下一步、步骤列表和进度。第一步不能后退，最后一步不能前进；到达最后一步不自动停止。
- 讲解中的代码块仅用于阅读。文件备注不执行命令，正文不获得执行脚本、修改源码或插入代码的能力。
- Markdown 正文支持段落、标题、列表、行内代码、粗体、代码块和普通链接。具体原生排版效果必须实际检查，不能因为文件是 Markdown 就宣称阅读效果合格。
- 2026-10-22 请求者确认[代码块效果图](../../docs/plans/images/inline-explanation-approved.png)：代码框须有独立底色、细边框及四周留白，与下面的简短中文翻译明显分开。原生评论仅提供代码高亮不足以通过验收；保持代码旁显示，不修改用户主题、全局设置或 VS Code 安装文件。讲解文件仍使用普通 Markdown，保存后自动更新及现有普通、diff 导航继续有效。
- 0.1.3 在原生评论中以内存矢量图显示代码框，避免依赖评论不提供的自定义样式。Markdown 原文及正文入口保留，复制代码从原 Markdown 进行；原始 HTML 先按文字处理，不因内部图片显示启用作者提供的 HTML。该显示方式的限制须在使用说明中写明。

### 自动更新和进度

- 保存当前讲解文件后自动读取。重排及正文变化时按同一个步骤标识保留位置，不能用旧编号猜测；步骤被删除则回第一步。讲解标识改变视为另一份讲解，从第一步开始。
- 讲解输入以已保存文件为准，未保存的讲解正文编辑不替换当前内容；这与源码校验使用编辑器当前内容的规则分开。原 Markdown 的编辑器内容若已与成功加载的内容不同，正文回看不能按旧行号跳到无关段落。
- 只有新文件的全部结构检查通过后才替换当前讲解。JSON 未写完、缺少必要定位信息、重复标识、版本不支持或文件暂时读不到时，继续使用当前已接受的内容，明确显示新内容未加载及具体原因。
- 保留的旧正文仍须对照最新源码检查。无效文件更新不能成为忽略源码变化的理由。文件修好并保存后自动加载，错误提示随成功加载解除。
- 当前讲解尚未成功打开时没有旧内容可保留：说明错误，不创建半份阅读状态。
- 多次保存、切换步骤、打开另一份讲解和停止都可能遇到正在进行的读取。较早的结果不能覆盖较新的选择，停止后也不能重新显示正文。优先沿用编辑器已有的取消、更新及释放机制，只为实际未覆盖的异步调用增加必要处理。
- 打开另一份讲解期间，旧源码或旧讲解的变化通知不能取消新的打开操作；发生变化时先清除旧显示。新文件被取消或无法接受后，重新读取并检查旧讲解的最新保存内容及源码，不直接恢复旧位置。明确的后续导航、正文或停止操作仍可以取代正在打开的请求。
- 重新主动打开同一份讲解时恢复步骤标识；找不到该步骤则回第一步。启动编辑器不自动打开讲解。读取完成的内容仍须重新校验，不能直接复用上次的位置。
- 停止、替换讲解或扩展停用时，清除相应正文与突出显示，解除文件订阅并取消或忽略不再需要的读取。用户的代码页保持打开。进度保留，活动正文及源码读取结果不作为持久数据保存。

### 手动验收

每项记录实际操作、结果及必要截图。未经操作的项目标为“未验证”，不可只凭格式解析或单元检查判定通过。

2026-10-21 请求者要求减少手动操作，授权在不抢夺控制权、不切换窗口的条件下自行验证。允许在独立 Windows 桌面中运行真实 VS Code，使用独立配置、扩展目录和演示仓库；通过真实命令、编辑器文档及测试进程自身的界面读取检查。进度跨进程检查使用普通实例的真实磁盘存储，不以官方扩展测试模式的内存存储替代。禁止向当前桌面发送输入、激活或切换窗口。以下用例能由实际运行及截图证明时可记录为后台验证通过，不能据此省略未覆盖的交互或阅读效果；单元检查仍不替代真实 VS Code 结果。

| 10 | 在变动后的文件中制造两个完全相同的目标范围，即使旧行号处仍然匹配 | 不选第一个、不偏信旧行号；提示存在多个对应位置并按无效步骤处理 |
| 11 | 只改文件中不被该步引用的其他位置 | 唯一目标仍可阅读，提示文件已有其他修改；不能声称已验证整个业务说明 |
| 12 | 移除文件、使用不存在的提交，或把需要存在的 Git 文件引用改为不存在的路径 | 说明具体缺失对象，不回退到其他文件或版本；其他步骤不被整份阻断 |
| 13 | 为整个新增或删除文件准备存在与不存在的两侧 | 不存在侧显示为空，但只有确认该版本确实没有该文件时才成立；不存在侧不能有目标范围 |
| 14 | 讲解双侧目标中只改坏一侧 | 该步骤不再作为有效双侧讲解显示，不留下另一侧正文制造仍完全对应的印象 |
| 15 | 改动讲解正文并保存，再重排步骤但保留标识 | 自动更新正文，仍停在同一个步骤，当前编号随新顺序变化 |
| 16 | 删除当前步骤；再把文件中的讲解标识改为新值 | 分别回到第一步；不会用旧编号或旧进度指向无关内容 |
| 17 | 保存不完整备注、重复步骤标识、错误范围字段或未知格式版本 | 旧的有效内容继续可读；说明新内容没有加载及原因，不接受半份新文件 |
| 18 | 在无效更新仍存在时同时修改源码，再修好讲解文件并保存 | 原讲解仍执行代码检查；修好后自动更新，解除文件错误提示 |
| 19 | 让讲解文件暂时不可读后恢复，并测试第一次打开就无效的文件 | 活动讲解可保留旧内容并在恢复后更新；首次打开无旧内容时只说明错误，不创建部分阅读 |
| 20 | 停止后重新主动打开；再重新启动 VS Code | 主动打开恢复有效步骤；不存在的步骤回第一步；启动时不自动开始 |
| 21 | 读完最后一步，再停止 | 最后一步内容保留直到停止；停止清除正文和突出显示，保留代码页及进度 |
| 22 | 混合普通文件、历史 diff 和未提交 diff 连续跳转 | 每一步读取自己的引用，不混淆同一路径的当前文件与历史版本 |
| 23 | 打开另一份讲解、取消文件选择、尝试打开无效讲解 | 成功打开才替换；取消或无效文件不破坏现有阅读；两份讲解的进度不混用 |
| 24 | 未提交比较打开后产生新的 Git 提交 | 旧比较提示基准已变化，需要更新讲解；固定提交比较不受当前 HEAD 变化影响 |
| 25 | 使用多段较长的真实逐句说明，包含列表、行内代码、代码块和普通链接 | 正文可阅读，无截断或重叠；文字对应实际代码；不要靠宽表格和重复固定栏目掩盖问题 |
| 26 | 全程前后检查源码、暂存区、HEAD 和未保存状态 | 插件没有保存或改写源码、插入标记、检出历史文件或修改暂存区 |

### 必要的自动化与现有检查

- 实施后运行项目实际提供的编译、类型检查和与改动直接相关的已有检查；当前实际命令及结果见上文。格式与顺序检查不替代界面观察，真实 VS Code 后台结果仅证明实际运行的场景。
- 需要一组可控制读取完成顺序的检查，覆盖快速切换步骤、连续文件保存、替换讲解和停止后旧读取才完成的情况。手动操作无法可靠固定这些先后顺序；通过条件是最后只显示当前有效选择，停止后没有任何迟到结果重新出现。
- 上述检查沿用实际读取接口及其生命周期。不能只为测试新增生产转发层、独立执行流程或多份活动状态。格式检查另需有限的自动检查：JavaScript 的正则、模板、注释、符号边界和自动插入分号受不同语法上下文影响，不能只靠本次分号前空格的手动案例证明不会误接讲解。直接检查生成摘要与实际定位入口，覆盖允许和拒绝的具体输入，不建设另一套阅读流程。

- 首版及未来版本读取 CodeTour 的 `.tour` 文件。
- 首版读取独立 HTML 文件、执行讲解中的脚本或代码插入命令。
- 自动扫描讲解目录、单独的暂存区比较、同时活动的多份讲解。
- 找不到目标时猜测位置、按相似含义匹配、自动搜索重命名后的其他文件。
- 为无效步骤另做独立阅读面板、仅用侧栏替代有效步骤的行内显示。

- 将文档格式或示例检查通过当作真实行内与 diff 显示验收通过。
